# P03 查找史料：发现、自动核验与推荐设计

> 版本：0.1
> 日期：2026-09-02
> 状态：产品边界已获用户认可；用户已明确授权本次跳过页面图、直接实现 P03
> 边界：只定义教师可观察行为和前端需求，不设计数据库表、具体后端 API、检索索引或服务端模块

## 1. 教师任务与页面职责

教师完成 P02 后，不应再充当史料核验员或逐字段填写价值卡。P03 的唯一任务是：围绕已确认的探究问题，直接提供一组可阅读、可追溯、已完成基础自动核验且有推荐理由的史料，让教师通过阅读、比较和取舍形成课堂史料组。

```text
已确认探究问题
→ 项目内轻量 RAG 优先发现
→ 覆盖不足时补充外部权威公开来源
→ 系统自动完成来源、定位、内容对应、权利和教学适配检查
→ 只把达到可用门槛的史料放入可选区
→ 教师直接阅读、选择、替换或排除
→ 进入 P05 组织主张—证据关系
```

P04 不再是独立教师页面或导航步骤。原 P04 的溯源、加工、问题相对价值与局限仍作为 MUST-004 的内部必经能力，其结果嵌入 P03 史料卡和后续审计。未知、冲突或失败不能被包装成“系统已核验准确”。

## 2. P02 到 P03 的衔接

- P02 先给 2—3 个可直接采用的中心问题方案；只有信息确实不足时才提出少量必须确认的问题。
- 首版通过提示词工程、结构化输出、确定性规则和质量评测稳定结果，不把“模型微调”列为当前承诺。
- 只有在积累了经授权、去标识、高质量样本并建立稳定离线评测后，才重新判断微调是否优于提示词/RAG；这属于后续模型能力变更，不在 P03 前端编码中实施。
- P03 继承已确认问题、课时和教材锚点，自动整理史料用途、建议数量和类型构成。教师可调整，但无需先完成一张查找条件表。

## 3. 候选发现与自动核验

发现顺序是产品优先级，不规定具体技术实现：

1. 先从项目已登记、可追溯的轻量知识库中寻找候选。
2. 类型、观点或数量覆盖不足时，再查询外部权威公开来源。
3. 普通网页和二次转载只作为定位原始来源的线索，不直接进入可用区。
4. 对同一馆藏号、稳定 URL、版本或内容指纹进行去重；不因重复结果增加推荐权重。
5. 每条材料进入可用区前，至少完成来源身份、稳定定位、摘录对应、加工边界、权利展示范围和当前问题适配检查。

自动核验结果分为：

- `可用`：基础核验通过，可供教师选择；不表示史料无偏向或能证明所有主张。
- `有条件可用`：限制清楚且仍可在当前课堂场景合法、准确地使用；限制必须紧邻内容展示。
- `核验中`：不得进入默认可选区，可显示不含史料内容的进度摘要。
- `不可用`：定位、内容、权利或处理失败；与可用结果隔离，只在“未采用结果”中说明原因。

教师不负责把状态从“待核验”改成“已核验”。教师负责阅读、比较、选择、替换、排除和最终批准；系统负责给出可复核依据并对不确定性诚实降级。

## 4. 默认结果与推荐排序

- 正常结果池目标为 8—12 条，默认突出推荐 4—6 条；公开 Demo 使用 10 条候选、4 条优先推荐的确定性预生成状态。
- 不显示伪精确的综合分数。排序必须能用自然语言解释。
- 排序至少考虑：问题匹配、来源权威与可定位性、史料类型互补、支持/质疑/语境功能互补、学段可读性、课时适配和权利展示范围。
- 推荐列表不能全由同一来源、同一史料类型或同一立场构成；不足时明确显示覆盖缺口。
- 教师调整排序条件、排除或选择后，已选内容保持不变，不自动替换教师决定。

## 5. 页面内容与交互

页面以 P01 教学情境页为视觉母版，使用低眩光史料阅览台、纸张工作卡、左侧证据脉络和桌面双栏。它不是搜索后台或数据表格。

### 5.1 首屏

- 显示当前探究问题及 `查看问题`；只查看上游时可自由往返，实际修改后才提示影响。
- 先显示 `为本课优先推荐 4 条`，其后是 `更多可用史料`。
- 右侧显示系统自动整理的史料组合：建议数量、类型构成、选择进度和仍缺的证据视角。
- 搜索范围、类型和排序调整收进渐进展开区，不用一排密集筛选器占据首屏。

### 5.2 史料卡

每条史料卡直接提供：

1. 在许可范围内可直接阅读的摘录、转写或图片预览；
2. 题名、作者/制作者、年代、类型、来源机构和稳定定位；
3. `为什么推荐`：它与当前问题、课时和已有史料组的关系；
4. `可以帮助判断` 与 `不能单独证明`；
5. 权利与展示限制、访问日期和官方来源入口；
6. `选入本课`、`不采用`、`查看完整依据`。

官方链接是追溯入口，不是阅读史料的唯一方式。许可允许时直接展示必要内容；图片或全文再使用许可不清时，不复制整份材料，只展示合法必要节选、元数据和官方预览/链接。AI 概括、翻译或教学说明必须与史料原文分开标识。

### 5.3 教师自有材料

静态 Demo 只提供 `录入我有权使用的材料元数据`，不伪造文件上传或在线核验成功。完整模式未来可以接收教师合法材料，但必须先提示不得包含真实学生/敏感信息，且“有权用于当前处理”不等于允许公开再分发。

## 6. 状态与恢复

| 状态 | 可观察行为 |
|---|---|
| 正常 | 推荐区与更多结果可阅读；选择即时更新史料组；理由和限制不折叠消失 |
| 加载 | 已完成结果继续可读；新发现按来源分项显示，不用虚假百分比 |
| 空 | 区分知识库无覆盖、外部来源无可用结果和筛选后无匹配；提供调整问题或录入元数据 |
| 校验失败 | 自有材料元数据错误就地显示并聚焦首错；不影响公开候选 |
| 系统/部分失败 | 成功结果保留；失败来源单列，可重试或继续使用当前结果 |
| 无权限/不可用 | 进入 P12，不透露候选、问题或材料是否存在 |
| 超时/离线 | 显示已完成范围；允许使用已缓存 Demo 结果，不把未完成外部核验标为可用 |
| 成功 | `已选入本课史料组` 与行内状态一致；可撤销时提供明确入口 |
| 手机窄屏 | 单列史料卡；内容、理由、限制和主动作顺序阅读，不缩小桌面双栏 |
| 键盘/焦点 | 结果为语义列表；展开、选择、排除和来源链接均可键盘完成；异步更新不抢焦点 |

## 7. Demo 与完整模式边界

- Demo 使用已登记的官方权威来源与预生成核验/推荐结果，明确标记为演示；不连接在线 RAG、联网搜索、付费 AI、数据库或真实上传。
- 非史料的推荐理由、失败状态和教学情境可以合成，但必须标明演示性质；史料本体、摘录、题名、来源、版本和馆藏信息不得合成。
- 完整模式未来必须由权威服务端执行真实核验、授权、隔离、费用限制和外部访问；前端状态只改善体验，不构成安全授权。

## 8. P03 编码前验收门

1. 本次由用户明确取消页面图前置门禁；实现仍须以 P01 为视觉母版，移动端依据同一结构重排，不另造视觉体系。
2. 史料卡在页面内直接呈现可合法展示的内容、推荐理由、用途与局限，而非只给外链。
3. 默认结果体现“较多候选 + 少量优先推荐”，且没有单一可信度分数。
4. 不存在独立 P04 教师核验页或 `继续核验价值卡` 主路径。
5. 正常、加载、空、校验失败、部分失败、不可用、离线/超时、成功、320px 和键盘/焦点均有确定性 fixture 落点。
6. 不新增依赖，不设计数据库或具体后端 API，不调用真实联网检索/AI，不使用合成史料或许可不明图片/全文。

## 9. 当前未验证

- 推荐 4—6 条、结果池 8—12 条是否符合教师实际比较负担，需 5 名教师任务测试。
- 自动核验能否在可接受成本和时间内达到引用零错配目标，需后续数据库/后端设计和真实评测证明。
- 三条已登记官方来源目前只确认元数据与链接展示边界；任何摘录或图片进入 Demo 前仍需逐条许可与定位复核。
- 页面视觉和手机重排仍需以真实浏览器验证；后续页面继续执行“先讨论、页面图确认、再编码”。
