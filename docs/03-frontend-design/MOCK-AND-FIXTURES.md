# 合成非史料数据与 Mock 方案

> 状态：阶段 5 已批准归档
> 当前修订：2026-09-02 P03 10 条官方候选目标与预生成发现/核验边界已随阶段 6.6 获准归档
> 规则：教学情境、用户输入、错误和系统状态使用 G0 合成数据；史料只能使用官方/权威公开来源，绝不合成；阶段 12 前不使用真实教师/学生/课堂数据

## 1. 目标

Mock 不只是让页面“有东西可看”，而要用同一前端需求契约证明所有页面状态、上游回退、重复提交、离线、权限安全展示和导出边界。Demo adapter 与未来真实 adapter 必须通过同一契约测试。Mock 可以合成界面状态，但不能伪造史料、官方出处、馆藏号、引文或许可。

## 2. Fixture 包结构（设计）

每个 fixture 包包含：稳定 ID、schema/contract 版本、生成说明、数据分类、许可说明、适用需求、初始任务快照、预期页面状态、允许操作与预期结果、故障注入配置。史料对象另带官方来源、稳定 URL、版本/馆藏号、定位、访问日期、权利限制和复核记录。字段名、JSON 根包、adapter 能力和场景注入已在 `VIEW-MODEL-FIXTURE-SPEC.md` 冻结；文件物理路径在阶段 6 按批准代码目录落实。

不得从真实个人数据改名；不得编造或改写历史材料充当史料；不得粘贴许可不明全文；不得使用真实 API 响应、密钥、数据库导出或隐私截图。

## 3. 基准任务

`FX-TANG-45M-V1`：对应 PRD 首个示范课程。学情、教师操作、活动草稿、量规草稿、错误和异步状态是合成数据；史料使用 `SOURCE-FIXTURE-RESEARCH.md` 已登记的真实官方来源。

- 学情：高一、45 分钟、合成班级困难“区分材料信息/观点/解释”。
- 中心问题：沿用 P02 当前确认版“依据不同类型的史料，‘盛世’能在多大程度上概括唐朝前期？”
- 官方史料起始登记：`AUTH-SRC-001` 国家图书馆《贞观政要》版本记录、`AUTH-SRC-002` 中国国家博物馆三彩釉陶载乐骆驼、`AUTH-SRC-003` 故宫博物院《步辇图》馆藏记录。P03 正常态目标为 10 条候选、其中 4 条优先推荐；其余史料必须逐条完成官方来源与许可登记后才能加入 fixture，当前不得合成补足数量。
- 关系：支持、质疑、语境补充和不能支持各至少一条。
- 史料用途：比较不同来源对同一问题的记载；检验一种历史说法是否站得住。
- 活动：阅读、比较、讨论，个人用 120—150 字回答中心问题并标出至少两项材料依据；总时长精确含转场。
- 量规：证据选择/引用、解释、互证/质疑、结论边界四维。
- 展示说明：“教学情境和操作结果为合成演示；史料元数据来自所列官方页面。图片/全文未获开放许可时不收录。”

该基准只验证前端闭环。发现顺序、自动核验和推荐均为预生成演示状态，不伪装真实 RAG、联网搜索或模型调用。官方来源并不自动证明某项史学主张；公开 Demo 上线前仍须完成精确引文、版本、许可和外部历史教师复核。许可不明确的图片/全文继续只展示元数据、合法必要节选和官方预览/链接。

P00 的敦煌艺术序章与 `FX-TANG-45M-V1` 分离：它是带常驻“艺术化演绎”标签的品牌视觉资产，不是 `SourceSummaryVM`、不参与史料筛选、关系图或教学包。进入任务后必须明确显示唐史 fixture 的题目，避免把敦煌场景误当课程证据。

## 4. 场景目录

| `S01-EMPTY` | 无任务/无候选/无关系/无活动 | 每页空状态与主动作 |
| `S02-VALIDATION` | 课时 0、空问题、超长标题、缺定位 | 首错聚焦、摘要、输入保留 |

| `S10-UPSTREAM-CHANGE` | 已批准后改中心问题/史料 | 影响预览、下游待复核 |
| `S11-AUDIT-BLOCKER` | 同源、课时超限、缺量规维度 | 阻断定位且不能绕过 |
| `S12-STORAGE-FAILURE` | IndexedDB 不可用/写失败 | 保存风险、内存会话、导出/退出路径 |
| `S13-LONG-CONTENT` | 长古文、长 URL、50+ 候选、特殊字符 | 换行、虚拟化/分页设计、性能 |
| `S14-CLEAR` | 当前任务含所有对象 | 影响确认、成功终态、不可恢复 |
| `S15-MEDIA-FALLBACK` | 影片超时/解码失败 | 依次降到响应式静态海报或纯色；主动作和文字不变 |
| `S16-INTRO-RETURN` | 从任务返回 P00 | 显示可用海报/影片终态；不阻断进入动作 |

| `S18-LOW-PERFORMANCE` | 低帧率/资源超时/节省数据 | 自动选择轻量/静态，不下载无用完整媒体 |

## 5. 故障注入方式

Mock adapter 接受仅在开发/测试可用的 scenario 配置，按动作返回确定性延迟、错误或部分成功。公开 Demo 不显示能伪装服务端状态的工程开关；测试通过启动参数/夹具选择触发。

- `latency`: 0ms、1.5s、31s；31s 场景必须能取消。
- `failureAt`: 指定加载/保存/核验/审计/导出/清除步骤。
- `offlineAt`: 指定路由进入后断线。
- `duplicate`: 复用 operation ID 和相同结果。
- `conflictVersion`: 返回权威版与教师草稿。
- `storageUnavailable`: 禁止 IndexedDB，验证风险展示。
- `narrativeCapability`: `full3d/lightMotion/static/safeColor`，并可注入 media decode/context lost/slow frame。
- `filmState`: 影片 loading/ready/error；故障注入只用于测试媒体回退，不伪造业务成功。

真实时间通过可控时钟/假定时器；测试不实际等待 31 秒。

## 6. Mock 行为约束

- 不能把未实现的真实 AI、数据库或授权伪装成在线成功；所有生成内容标“预生成合成结果”。
- Mock 的 `authorization` 只能验证安全展示，不证明服务端隔离；完整模式仍需负向授权测试。
- Mock 的发现、核验和推荐状态只验证 UI 状态机，不证明真实 RAG、史料真伪/许可或模型质量；史料事实仍须来自官方登记并逐条核对。
- IndexedDB key 含 contract/fixture 版本；不保存密钥、capability、真实文件或跨任务材料。
- 清除要覆盖任务快照、草稿、缓存和生成的本机文件引用；重复清除一致。

## 7. 契约与页面测试映射

每个页面至少以 3 类 fixture 测试：正常、页面主失败、跨页面上游回退；再由 E2E 覆盖 `S00`、`S07`、`S08`、`S10`、`S11`、`S14` 和 P00 的 `S15`—`S18`。`PAGE-STATE-MATRIX.md` 的每一格需对应组件或 E2E 断言，不能只依赖截图。

## 8. 许可与审查记录

史料加入 fixture 前逐项记录官方机构、来源、版本/馆藏号、定位、许可证/合理使用边界、允许存入仓库的范围、加工和复核人。许可未知只保存必要元数据、稳定链接和必要短引，不能把正文/图片放入仓库。当前已登记 3 条官方候选，但没有下载或复制馆藏图片/古籍全文。

艺术资产单独记录在 `assets/README.md`，不得借“AI 生成”状态绕过史实、误导或公开资产审查。
