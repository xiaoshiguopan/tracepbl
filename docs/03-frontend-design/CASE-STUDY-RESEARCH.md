# 阶段 5 前端案例与规范研究

> 研究日期：2026-08-31（Asia/Shanghai）
> 状态：阶段 5 已批准归档
> 范围：复杂工作台、来源元数据、可恢复操作、响应式和无障碍；只读研究，不复制代码

## 1. 研究问题与选择标准

本轮不是寻找一套可直接套用的界面，而是回答四个问题：复杂证据工作如何保持“当前任务”清楚；来源、定位和加工信息如何与正文并存；上游改变怎样让影响与恢复可见；桌面密集工作台如何降级为窄屏线性流程。

按 `MASTER-PLAN.md`，案例需核对当前 Star、维护、测试/CI、文档、安全或 Issue 响应与许可证。Star 只作为采用度信号。研究没有改变 React/Vite 唯一技术栈，也没有克隆或安装任何仓库。

## 3. 案例做法到史证工坊的映射

| 案例做法 | 对应需求/风险 | 采纳、调整或淘汰 |
|---|---|---|
| Zotero 的集合—条目—详情三栏 | MUST-003/004；教师需在候选集合和单张价值卡间保持上下文 | **调整采纳**：桌面使用“候选列表 + 当前详情”；窄屏改为列表到详情的标准导航，不保留三栏挤压 |
| Zotero 把元数据、附件、笔记分面呈现 | 来源与加工必须可区分 | **调整采纳**：史证工坊固定为“出处与许可 / 原文与定位 / 加工 / 价值与局限”，不允许用户自由隐藏门禁字段 |
| Zotero 集合只是同一条目的组织视图 | 同一史料不同节选不应静默复制 | **采纳概念**：来源记录与节选/用途分开；仅写入前端需求，不推断数据库表 |
| OpenRefine 侧栏筛选与匹配数量 | 候选多时需看清当前过滤范围 | **调整采纳**：筛选条件进入 URL；导出/批量操作前明确“作用于当前选择还是全部” |
| OpenRefine 操作历史与可回退时间线 | MUST-004—009 上游变更、误删与恢复 | **采纳原则**：显示最近安全状态、受影响对象和撤销窗口；不承诺无限历史或跨设备恢复 |
| OpenRefine 预览后应用转换 | 替换、重新生成和批量修改可能覆盖教师编辑 | **采纳**：先展示差异和影响，再确认应用；失败时保留当前确认版 |
| Tropy 可定制元数据模板与必填提示 | 不同史料类型有公共字段与类型补充字段 | **调整采纳**：界面按史料类型显隐补充字段，但字段集合由已批准 PRD 固定，不提供 v0.1 模板编辑器 |
| Tropy 项目视图/条目视图和键盘移动 | 教师需快速核对多条史料 | **采纳**：桌面提供上一条/下一条；快捷键仅作增强，所有动作仍有可见按钮 |
| Tropy 在局部选区上附注和元数据 | 引文必须定位到页/段/图像区域 | **采纳概念**：证据卡显示定位片段和可访问的文字等价；本阶段不设计图像编辑器 |
| 三个案例的桌面高密度可拖拽 UI | NFR-006/007；320px、键盘和触屏 | **淘汰**：拖拽不是唯一操作；窄屏用顺序列表与显式“移动/关联”表单 |

## 4. 官方规范与实现约束

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 作为 AA 设计目标；重点包括键盘、状态消息、文本缩放、对比度、焦点不被遮挡和 24×24 CSS px 最小目标。
- [WAI-ARIA APG Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) 用于折叠细节：原生按钮、`aria-expanded`，Enter/Space 可操作。APG 是交互模式参考，不代替真实读屏测试。
- [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines) 当前规则用于前端设计自审：语义 HTML 优先、表单持久标签、就地错误与首错聚焦、异步状态 live region、URL 反映筛选/页签、破坏性操作确认或可撤销。
- [OpenRefine 用户手册](https://openrefine.org/docs/manual/running/) 证明历史与筛选状态需要区分；[Zotero 快速指南](https://www.zotero.org/support/quick_start_guide) 说明列表与详情元数据并存的价值；[Tropy 界面说明](https://docs.tropy.org/using-tropy/intro-to-the-interface) 提供史料项目/条目双视图参考。

## 6. 研究结论

史证工坊不应模仿“聊天窗口 + 生成按钮”，也不应复刻桌面研究软件的三栏密度。最终方向是“两幕式证据审阅工作台”：P00 用敦煌藏经洞的非阻塞电影化叙事建立历史厚度；进入任务后用稳定的任务脉络带显示主链与阻断，用列表/详情切换承载史料密度，用差异预览和影响清单保护教师编辑，并在窄屏把同一结构线性化。视觉、交互和数据需求分别落在 `VISUAL-DIRECTION.md`、`PAGE-SPECIFICATIONS.md` 和 `VIEW-MODEL-FIXTURE-SPEC.md`。
