## 2. 产品摘要

### 2.1 问题

中学历史教师能够使用通用搜索、聊天式 AI 或资源平台找到大量内容，但仍要独自完成四项高风险工作：确认史料究竟来自哪里、判断它对当前问题有什么价值与局限、把史料转化成学生必须使用证据才能完成的活动，以及设计真正评价证据推理而非答案相似度的量规。现有替代方案通常只覆盖其中一段，容易留下伪造引用、脱离语境、活动与评价错位及教师核验负担过重的问题。

### 2.2 v0.1 产品定义

TracePBL v0.1 是面向中学历史教师的证据探究设计工作台。教师先描述教学情境，再输入一个主题、事件、概念或观点；系统协助其收束探究问题、发现或接收史料、建立可核验的出处与加工记录、判断史料相对该问题的价值与局限，并生成彼此对齐的课堂活动、学生支架和评价量规。所有可交付内容必须经过教师逐项审核，AI 不自动发布，也不替代教师的历史判断。

### 2.3 最小核心闭环

```text
教学情境
→ 输入主题/事件/概念/观点
→ 收束并确认探究问题
→ 发现或导入候选史料
→ 核验出处、加工记录、价值与局限
→ 建立主张—证据关系
→ 生成证据依赖的活动与分层支架
→ 生成证据对齐的评价量规
→ 整体审计
→ 教师修改、逐项批准并导出教学包
```

若史料无法核验、主张缺少证据、活动不需要使用证据或量规没有评价证据推理，闭环必须停在审计或教师审核处，不得生成“可交付”状态。

## 3. 目标、指标与非目标

### 3.1 产品目标

1. 让教师在生成活动前先完成学段、教材、课时和学情描述，避免一套材料适配所有课堂。
2. 让每条进入教学包的史料都可追到相符来源，并能区分原文、节选、翻译/转述、教学支架和 AI 生成内容。
3. 让史料价值判断始终相对于当前探究问题，并呈现适用范围与局限，而不是给出脱离问题的单一“可信度分数”。
4. 让课堂活动、学生支架和评价量规形成同一个证据推理闭环。
5. 在不降低引用安全的前提下，降低教师的检索、核验和设计返工时间，并保留教师的修改、否决和最终批准权。

### 3.2 与章程指标的关系

| PRD 结果 | 对应章程指标 | v0.1 验证重点 |
|---|---|---|
| 可试教且全链可追溯的教学包 | M-01、M-03、M-06 | 至少 4/5 真实教师任务达到定义；可交付引用 100% 可解析且相符 |
| 教师实际审查史料价值卡 | M-04 | 至少 4/5 教师主动修改、替换或否决至少 1 张卡 |
| 备课效率改善 | M-05 | 中位总耗时或核查返工时间下降至少 30%，且引用安全不下降 |
| 活动—量规一致 | M-07 | 5/5 核心活动必须使用证据，量规必须评价证据推理 |
| 专业复核、成本与周期受控 | M-08～M-10 | 外部历史教师复核无阻断项；不突破成本和 12 周边界 |

指标采集仅使用参与者编号、任务类型、耗时、关键操作和去标识化评价；不得采集真实学生信息。指标基线、样本和判定规则以章程为准，不在本 PRD 中重复发明。

### 3.3 v0.1 非目标

- 不证明学生学习成效；v0.1 只验证教师工作流和教学包可试教性。
- 不替代教师做历史事实、史料价值、课堂适用性或学生成绩的最终判断。
- 不建设完整课程管理、学校管理、内容商城、古籍库、论文库或博物馆数据库。
- 不以生成速度、材料数量或视觉效果作为主要成功标准。

## 4. 用户、场景与工作

### 4.1 第一用户：中学历史教师

不限定某一年级。教师可能教授初中或高中，内容可能属于中国古代史、近现代史、世界史或地方史；系统必须先理解具体教学情境，再调整材料和支架。

优先场景：

1. 公开课或教学比赛：需要出处可靠、设计理由可说明、成果可复核。
2. 一至两课时的史料探究课或微型 PBL：需要在真实课时内完成证据推理，而不是做大型项目。
3. 课程研发团队的示范课程：需要可复用、可审查的专业产物，但 v0.1 不做团队协作权限。

核心待办：

> 当我拿到一个新的历史主题、事件、概念或观点时，我希望在具体学段、课时和学情约束下，快速得到来源可核验、难度合适、活动与评价一致的探究课材料，以便我有依据地修改并用于备课，而不是重新查证 AI 的每一句话。

### 4.2 次级用户：历史教研人员或课程研发教师

其任务与第一用户相同，但更关注样例的可解释性和复用性。v0.1 允许其以普通教师身份查看和评价产物，不提供组织空间、共同编辑、审批流或角色权限。

### 4.3 非目标用户

- 直接使用通用问答的学生；学生端 AI 伴学留到后续验证。
- 只需一键教案/PPT、不愿核查来源的教师。
- 需要 LMS、班级、作业、成绩、支付或课程运营的学校和机构。
- 需要学术论文管理或完整专业数据库的研究者。

## 5. 产品原则与统一业务规则

### 5.1 证据优先

- 先确认问题，再判断史料价值；同一史料对不同问题可有不同价值与局限。
- 不显示脱离问题的总分式“史料可信度”。核验状态与问题相对价值是两个不同字段。
- 不把“来源看起来权威”当作“它足以支持当前主张”。
- 可交付教学包中的核心主张至少连接一条已核验史料；需要综合判断的核心主张原则上连接至少两种不同类型史料，若不足必须显著标记证据局限并由教师确认。

### 5.2 来源与加工透明

每份材料必须区分并记录：

1. 原始来源或可核验版本；
2. 原文中的实际节选及删节位置；
3. 已存在的现代标点、翻译或释义及其来源；
4. 为教学新增的背景、词注、问题或支架；
5. AI 新生成的概括、改写或建议。

AI 概括、改写或翻译不得伪装成史料原文；找不到相符来源的材料不得进入可交付状态。

### 5.3 来源优先级

候选发现优先顺序如下，低优先级来源可以提供发现线索，但不自动成为最终依据：

1. 档案馆、博物馆、图书馆、权威古籍数据库、政府和教育主管部门等权威来源；
2. 大学、研究机构、开放学术出版和有明确作者/出版信息的研究成果；
3. 已核验版本的教材、课程标准和官方教学资源；
4. 普通网页、聚合页和二次转载，仅作为查找原始来源的线索。

### 5.4 来源状态机

```text
候选
→ 待核验
→ 已核验 / 有条件可用 / 已排除
→ 教师已批准
→ 可进入教学包
```

- “已核验”表示来源、引文和元数据能够对应，不表示该史料无偏向或能支持所有主张。
- “有条件可用”必须显示具体限制，只有教师明确接受限制后才能批准。
- “已排除”材料保留排除原因供当前任务审计，但不进入教学包。
- 来源内容、链接或加工记录变化后，原批准失效并回到待核验或待批准状态。

### 5.5 学情适配不是只改短文字

材料难度至少从以下维度判断：语言与古今差异、背景知识、信息密度、推理距离、隐含立场、互证难度、材料形式和所需认知操作。适配应优先保留原文和准确出处，通过背景、词注、结构提示、分层问题和比较工具搭建支架；任何删改必须可见。

### 5.6 教师是最终控制者

教师必须能查看、修改、替换、否决和批准每份核心史料及关键设计。系统不得自动公开、发送、共享或认定“已试教”；“导出”只产生交给当前教师的本地教学包，不等于外部发布。

## 6. 范围优先级

### 6.1 Must：v0.1 最小闭环

| ID | 能力 | 最小结果 |
|---|---|---|
| MUST-001 | 教学情境采集 | 形成经教师确认、足以驱动难度和课时约束的任务简报 |
| MUST-002 | 输入诊断与探究问题收束 | 将主题/事件/概念/观点转为教师确认的可探究问题 |
| MUST-003 | 候选史料发现与教师材料输入 | 获得有来源状态、可选择或排除的候选史料集合 |
| MUST-004 | 溯源、加工与问题相对价值卡 | 每份入选史料都有可核验出处、加工记录、价值与局限 |
| MUST-005 | 主张—证据关系图 | 核心主张与证据、反证、冲突及缺口可见 |
| MUST-006 | 证据依赖的活动与分层支架 | 学生不使用指定证据就不能完成核心任务 |
| MUST-007 | 证据对齐的评价量规 | 量规评价证据选择、解释、互证/质疑和结论边界 |
| MUST-008 | 全链路设计审计与交付门禁 | 发现并阻断伪造/错配来源及设计错位 |
| MUST-009 | 教师审阅、修改、批准与导出 | 教师逐项控制后获得可试教教学包 |
| MUST-010 | 临时数据、任务隔离与清除 | 无账号也不跨任务泄露内容，并能清除或恢复当前工作 |

### 6.2 Should：验证后优先增强

| ID | 能力 | 不作为 v0.1 发布阻断项的理由 |
|---|---|---|
| SHOULD-001 | 设备内可选保存常用教学默认值 | 可减少重复输入，但无账号的首轮任务可通过当前情境表完成 |
| SHOULD-002 | 更换史料后的影响传播提示 | 能降低返工，但 v0.1 可先由全链路审计指出受影响对象 |
| SHOULD-003 | 多份史料并排比较视图 | 有助于互证，核心比较仍可通过证据关系图与活动实现 |
| SHOULD-004 | 任务内命名检查点与多步撤销 | 提升探索安全感，v0.1 至少提供最后一步撤销与失败恢复 |
| SHOULD-005 | 教学包版式切换 | 有利于公开课/教研场景，但不影响内容闭环是否成立 |

| ID | 能力 | 前置条件 |
|---|---|---|
| COULD-001 | 教师个人史料收藏夹 | 需要先决定账号、持久化、版权和删除规则 |
| COULD-002 | 经授权的示范课程/模板库 | 需要内容许可、版本管理和公开发布审查 |
| COULD-003 | 学生端 AI 伴学 | 需单独验证学生需求，并完成未成年人、隐私、教师控制和安全变更审查 |
| COULD-004 | 团队评审与共享 | 需要账号、组织角色、资源归属和越权测试 |
| COULD-005 | 史料知识库或 RAG 增强 | 只有在来源覆盖、版权、维护成本和准确性证据支持时才考虑；它是实现候选而非产品形态 |

### 6.4 明确不做

- v0.1 学生端、真实学生作品处理或自动学生评分。
- PPT/动画自动生成、直播课堂控制或多 Agent 舞台展示。
- 账号注册、登录、个人云项目库、组织/管理员后台和跨用户协作。
- LMS、班级、学籍、作业、成绩、证书、课程商城、支付或订阅。
- 邮件、短信、定时任务、后台周期抓取或自动外发消息。
- 自动公开教学包、自动向第三方写入内容或自动替教师接受史料。
- 地方文化专用产品；地方史只与古代史、近现代史、世界史并列为可支持内容。
- 自建通用古籍、论文、教材、博物馆图片或版权内容数据库。
- 绕过付费墙、访问控制、许可限制或网站使用规则。
- 使用真实学生数据、可识别教师数据或未获授权的真实课堂材料进行开发、测试或演示。

## 7. Must 详细需求与验收场景

下列场景是后续设计、实现和测试的最低合同。所有 Must 都必须覆盖正常、失败、未登录、越权、边界、重复和恢复；“无账号”不是跳过身份/隔离检查的理由。

### MUST-001 教学情境采集

**用户故事**：作为中学历史教师，我希望系统在处理主题前先了解我的具体课堂，以便材料难度、任务长度和支架真正适合这一次教学。

**必需输入**：学段与年级、教材版本及单元/课次、课型、可用分钟数、学生已有知识、史料阅读水平、班级主要困难、希望培养的历史学科能力、期望产物。教师可标记“暂不确定”，但系统必须指出该不确定项会影响什么。

**验收规则**：

- 进入史料发现前，教师必须看到并确认一份任务简报。
- 系统只追问会实质改变材料、活动或评价的缺失信息；不要求教师填写学校、姓名、班级号或学生信息。
- 学段、分钟数、教材课次与任务范围冲突时，系统必须提示冲突并要求教师调整或确认取舍。
- 教师改变情境后，所有受影响且尚未重新确认的下游内容必须标记“需要复核”。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 教师完整输入后，系统展示可编辑任务简报；确认后才进入问题收束 |
| 失败 | 必需字段格式错误或服务失败时保留已输入内容，指出具体字段，不创建空白任务 |
| 未登录 | v0.1 无需注册或登录即可完成采集；界面不得以登录墙阻断核心闭环 |
| 越权 | 当前匿名任务不得读取、建议或预填来自另一任务/另一访问者的非公开情境 |
| 边界 | 课时为 0、负数、极端长时或主题范围明显超过课时时，阻止确认并给出缩小建议；初高中难度不得默认相同 |
| 重复 | 重复点击确认只产生一个当前任务简报，不复制任务或触发多次下游处理 |
| 恢复 | 失败或误改后可返回编辑；重新确认时明确列出哪些下游结果已失效、哪些仍可保留 |

**隐私/费用/外部副作用**：只收集教学所需的非个人情境；若输入疑似学生或敏感信息，提示删除并停止处理该部分。仅确认情境不应触发外部检索、付费调用、文件下载或消息发送；若后续 AI 诊断会产生费用，必须在开始前纳入任务成本记录。

### MUST-002 输入诊断与探究问题收束

**用户故事**：作为教师，我希望主题、事件、概念或观点被转成在当前课时内可由史料回答的问题，而不是得到宽泛教案。

**输入类型与处理重点**：

| 类型 | 至少诊断的维度 |
|---|---|
| 主题 | 时间、空间、对象和内容范围 |
| 事件 | 过程、因果、主体与不同视角 |
| 概念 | 定义边界、时代变化、迁移和反例 |
| 观点 | 支持证据、反证/替代解释、适用范围和结论限度 |

**验收规则**：

- 系统先展示输入类型判断及理由，教师可以改正类型。
- 至少给出一个中心问题建议，并说明它如何受学情、课时和教材锚点约束。
- 问题必须允许多个证据来源和有边界的结论；纯记忆题、答案预设题或无法在课时内完成的问题不得直接确认。
- 教师必须确认中心问题和预期学生证据产物后，才进入候选史料阶段。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 输入“隋唐时期的政治与经济”及 45 分钟情境后，系统建议缩到可由史料判断的中心问题，并由教师确认 |
| 失败 | 无法分类、内容含混或 AI 处理失败时，展示可编辑的最小澄清项，不伪造教师意图 |
| 未登录 | 无账号用户可完成诊断、修改和确认；不要求创建云项目 |
| 越权 | 不引用另一匿名任务的主题、私人材料或已确认问题作为本次事实 |
| 边界 | 空输入、仅一个无意义字符、超长粘贴、违法/超出历史教学范围或一课时无法覆盖的输入被拒绝或要求收束 |
| 重复 | 相同输入重复提交不产生多个互相竞争的当前问题；新结果出现前保留已确认版本 |
| 恢复 | 处理超时或教师否决建议后可保留原输入重新生成、手动改写或返回情境，不丢失已完成内容 |

**隐私/费用/外部副作用**：诊断不得要求个人或学生数据。AI 处理可能产生用量费用，需记录去内容化的调用次数/估算成本；不得把输入自动发送给未披露的第三方、自动搜索或公开。

### MUST-003 候选史料发现与教师材料输入

**用户故事**：作为教师，我希望从可信来源发现史料，也能粘贴或上传自己合法持有的材料，并清楚知道哪些只是线索、哪些已核验。

**验收规则**：

- 支持两条入口：按已确认问题发现公开候选；粘贴/上传教师有权用于当前任务的材料。允许教师只用其中一条或混合使用。
- 每条发现结果至少显示题名/名称、来源机构或作者、类型、稳定链接/馆藏号/标识符（若存在）、发现路径、访问日期、当前核验状态和权利/许可状态。
- 普通网页二次转载默认只能作为线索；系统应尽量定位原始或更权威版本，无法定位则不得标记已核验。
- 教师上传前必须确认材料不含敏感/真实学生信息且有权用于本次处理；上传不等于授权公开再分发。
- 允许教师纳入、排除、替换候选，并记录原因；无法核验或许可不明的全文/图片不得进入公开演示材料。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 系统按来源优先级返回与问题相关的多类型候选，教师也可加入合法材料，并看到各自状态 |
| 失败 | 外部来源不可达、解析失败或材料格式不支持时，明确失败对象和原因，其他候选仍可使用，并提供手动录入元数据路径 |
| 未登录 | 无账号用户可在当前任务发现和临时输入材料；系统不承诺跨设备保存 |
| 越权 | 任何访问者都不能看到另一任务的上传、候选选择或排除理由；不存在面向普通用户的后台候选池 |
| 边界 | 空文件、零字节、超出后续设计所定大小/类型、加密文件、疑似恶意内容、真实学生数据或无权处理内容被拒绝；极少/极多结果需显示缺口或要求收束 |
| 重复 | 同一 URL、馆藏号或文件重复加入时提示已有候选并合并选择，不静默复制或重复产生外部费用 |
| 恢复 | 搜索/解析中断后可重试单个来源、手动补录或移除失败项；已成功候选和教师选择保持不变 |

**隐私/费用/外部副作用**：上传内容按内部临时数据处理，不进入 Git、日志、截图或公开样例；发现请求可能把探究关键词发送到外部来源并产生 AI/检索费用，后续设计必须披露对象、设置超时/取消和成本记录。不得绕过付费墙、自动下载许可不明全文、写入第三方、发消息或公开材料。

### MUST-004 溯源、加工与问题相对价值卡

**用户故事**：作为教师，我希望每份入选史料都有一张能复核的证据卡，既说明出处和加工，也说明它对当前问题能证明什么、不能证明什么。

**通用字段**：题名/名称、作者/制作者、形成时间或年代、史料类型、来源机构/出版物、稳定链接/标识符、精确定位、访问日期、语言、权利/许可状态、核验状态、核验依据、内容摘录、删节标记、翻译/释义来源、教学加工、AI 加工、问题相对价值、局限和可支持/不能支持的主张。

**类型补充字段**：

- 古籍/文献：书名、卷/篇/章、使用版本、标点/翻译来源、精确位置。
- 文物/图像：保管机构、藏品/登记号、断代、出土或流传语境、尺寸、图像来源与许可。
- 学术研究：作者、题名、期刊/出版社、年份、页码、DOI 或稳定链接、访问状态。
- 教师上传：原文件名、教师权利确认、仅限当前任务标记和不得自动再分发说明。

**验收规则**：

- 引文必须能在所列版本和位置找到；题名相似、摘要转述或 AI 记忆不能代替核验。
- 价值判断必须引用已确认中心问题，至少回答“可用于回答什么、依据何种特征、局限/偏向是什么”。
- 原文、删节、翻译/转述、教学支架和 AI 生成内容在视觉与导出中保持可区分。
- 缺少关键字段时，卡片保持待核验；教师可补充，但不得一键跳过为已核验。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 入选史料形成完整卡片，教师能从引文打开/定位相符来源，并查看价值、局限与加工链 |
| 失败 | 链接失效、引文不符、元数据冲突或核验服务失败时降为待核验/已排除，指出冲突，不保留虚假“已核验” |
| 未登录 | 无账号用户可在当前任务查看和编辑证据卡；不以登录换取引用细节 |
| 越权 | 当前任务卡片不能引用或暴露另一任务的私有上传；只有当前教师可批准当前任务候选 |
| 边界 | 无作者古代材料、断代争议、多个版本、二手引文、无稳定 URL 或许可不明时允许记录“不确定”，但必须说明核验路径和使用限制 |
| 重复 | 同一史料的不同节选关联到同一来源记录；重复核验不覆盖教师批注、不重复计费且结果冲突时要求复核 |
| 恢复 | 来源恢复、教师补齐版本或改用替代来源后可重新核验；旧状态和变更理由在当前任务审计中可见 |

**隐私/费用/外部副作用**：卡片不复制不必要的版权全文或个人数据；仅保留完成教学和核验所需节选与元数据。核验可能访问外部网站/AI 并产生费用，必须可取消、可重试且记录去内容化用量。不得自动向来源站点写入、联系作者、公开卡片或把教师上传转换成公共资源。

### MUST-005 主张—证据关系图

**用户故事**：作为教师，我希望看清预期历史解释中的每条主张由哪些证据支持、质疑或限制，以便发现单一视角和证据缺口。

**验收规则**：

- 把中心问题拆成有限数量的核心主张或待判断子问题；教师可增删改。
- 每条关系标记“支持、质疑、补充语境或不能支持”，并要求简短理由。
- 显示史料类型、立场/形成语境和覆盖范围，提示单一来源、同源转述、证据冲突、过度概括及未连接主张。
- 关系图不得替教师消除真实史学争议；冲突可以保留并转化为课堂任务。
- 任一来源状态或中心问题变化后，受影响关系必须重新复核。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 教师可看到并编辑主张与多类史料的支持/质疑关系，缺口和冲突明确可见 |
| 失败 | 自动分析失败时保留史料卡，提供手动新建关系；不得生成无来源的默认结论 |
| 未登录 | 无账号用户可在当前任务构建和修改关系图 |
| 越权 | 不能连接另一匿名任务的主张或私有史料，也不能修改不属于当前任务的关系 |
| 边界 | 零史料、仅一份同源材料、证据互相冲突、主张过多或没有任何史料支持时，系统显示阻断/警告，不伪造共识 |
| 重复 | 重复建立同一主张—史料—关系时提示已有关系；改动关系不复制主张或史料 |
| 恢复 | 删除关系可撤销；替换/重新核验史料后可重新连接，原受影响活动和量规标记待复核 |

**隐私/费用/外部副作用**：关系图只使用当前任务已有内容；AI 分析记录去内容化费用，不把私有材料用于跨任务推荐或训练声明。该步骤无公开、发送、评分或第三方写入副作用。

### MUST-006 证据依赖的活动与分层支架

**用户故事**：作为教师，我希望获得能在真实课时内完成、并迫使学生引用和比较史料的活动，而不是读完材料也能凭教材答案完成的泛讨论。

**验收规则**：

- 每个核心活动必须绑定中心问题、使用的史料、预计分钟数、学生操作、可观察证据产物和对应学情困难。
- 核心活动的完成条件必须要求选择、引用、比较、质疑或限定证据；若不看史料也能完成，审计失败。
- 支架与难度维度对应，可包含背景、词注、结构提示、证据表、句式和分层问题；不得把答案直接写进支架。
- 总活动时间含转场、阅读、讨论和产出，不得超过情境中的可用分钟数；系统应明确取舍，不把完整教材内容都塞入一课时。
- 原文与教学加工继续可区分，史料删改不会被活动文本掩盖。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 系统生成有时间、史料、操作和证据产物的活动，教师可调序、改时长和改支架 |
| 失败 | AI 生成失败或某史料不可用时保留已确认问题/关系，明确缺失活动并允许手工编辑或换史料 |
| 未登录 | 无账号用户可生成、编辑和预览当前任务活动 |
| 越权 | 活动不得带入另一任务的上传、学情、教师批注或未批准史料 |
| 边界 | 课时极短、学生阅读能力低、史料过长、无多类型证据或总时长超限时，系统要求删减/增加支架/缩小问题，不用隐藏时间解决 |
| 重复 | 重复生成先展示差异并保留当前确认版；重复点击不覆盖教师编辑或触发不可见的多次费用 |
| 恢复 | 生成超时、误删或替换史料后，可保留教师编辑、撤销最近操作或从已确认关系重新生成受影响部分 |

**隐私/费用/外部副作用**：活动只基于合成学情和当前任务材料，不处理真实学生档案或作品。AI 生成可能产生费用，需可见、可取消、可局部重做；不得自动发给学生、LMS、邮箱或公开平台。

### MUST-007 证据对齐的评价量规

**用户故事**：作为不熟悉量规设计的历史教师，我希望系统依据学生实际要完成的证据产物生成可理解、可修改的量规，以便评价历史解释而不是只看答案是否接近参考答案。

**验收规则**：

- 量规只能在中心问题、证据产物和核心活动明确后生成。
- 必含四个维度：证据选择与引用、证据解释、互证/质疑、结论及其边界；可按任务删除不适用维度，但必须说明对 M-07 的影响。
- 每个维度使用可观察行为描述至少三个表现等级；不得使用“很好/一般/较差”等无证据锚点的空泛形容词。
- 量规必须引用实际任务中的史料操作和产物，不得评价课堂没有教或任务没有要求的能力。
- 量规仅用于教师形成性判断和反馈，不自动给真实学生最终成绩，不输出伪精确总分作为权威结论。
- 教师可以修改维度、等级和措辞，并看到修改后与活动/证据产物的对齐状态。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 系统从已确认活动和产物生成行为锚定量规，逐项显示对应任务证据并允许教师编辑 |
| 失败 | 活动或产物缺失、生成失败时不输出通用空壳量规，指出必须先补齐的上游项 |
| 未登录 | 无账号用户可生成、修改和预览量规，不要求保存学生名单或成绩 |
| 越权 | 不读取另一任务的量规、学生数据或教师批注；不存在自动调用管理员评分规则的入口 |
| 边界 | 只有一个简单事实题、没有证据产物、等级描述重叠、维度权重异常或教师删除所有证据维度时，阻断通过并说明原因 |
| 重复 | 重复生成保留教师当前版本并展示可选择替代，不静默覆盖；重复确认不创建多份最终量规 |
| 恢复 | 活动变化后量规标记待复核；教师可局部重建受影响维度、撤销误改或恢复最近确认版 |

**隐私/费用/外部副作用**：不输入真实学生姓名、作业或成绩；只处理任务和合成表现样例。生成调用需记录费用且支持局部重做；不向学生、家长、学校系统发送结果，不产生正式评分或其他外部后果。

### MUST-008 全链路设计审计与交付门禁

**用户故事**：作为教师，我希望在导出前得到一份明确、可操作的审计，防止来源错误、史料与主张脱节或量规评价错位进入教学包。

**审计类别**：

1. 来源完整性：引用能否解析到相符来源、版本/馆藏号/定位是否足够、许可状态是否允许当前输出。
2. 加工透明度：原文、删节、翻译/释义、支架和 AI 内容是否可区分。
3. 证据充分性：主张是否有支持、是否同源、是否忽略冲突、结论是否越过证据边界。
4. 课堂可行性：难度、活动时长、支架与学情是否一致。
5. 活动—评价一致性：不用证据能否完成核心活动，量规是否评价实际证据操作。
6. 数据与范围：是否混入个人/敏感数据、未授权材料、学生端或其他 v0.1 非范围内容。

**严重度**：阻断、需教师确认、建议改进。阻断项不能被“忽略全部”绕过；只有事实变化并重跑审计后才能关闭。需教师确认项必须记录具体理由。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 审计逐项显示通过/阻断/需确认/建议，并能定位到具体史料、主张、活动或量规；全部门禁满足后才允许标记可交付 |
| 失败 | 审计服务、链接检查或部分外部来源失败时状态为“审计未完成”，不把未知当通过 |
| 未登录 | 无账号用户可以运行完整审计；审计结果只属于当前任务 |
| 越权 | 不读取、对比或披露另一任务的材料/结果；普通访问者没有绕过阻断项的隐藏入口 |
| 边界 | 零史料、链接暂时不可达、条件可用来源、许可不明、全部材料同源、课时超限或量规维度缺失时按已定义严重度处理，不自动降级 |
| 重复 | 内容未变化时重复审计可复用仍有效检查并显示检查时间；内容变化时只复用不受影响项，不制造矛盾状态或重复外部费用 |
| 恢复 | 失败项修复后可重跑单项或全量审计；旧阻断项仅在新证据证明通过后关闭，并保留当前任务内的变更理由 |

**隐私/费用/外部副作用**：审计不把内容写入公共日志，不上传敏感材料，不保存跨任务画像。链接/AI 检查可能产生外部访问和费用，必须有超时、取消、重试及用量记录。审计本身不公开、发送、评分或批准材料。

### MUST-009 教师审阅、修改、批准与导出

**用户故事**：作为最终责任教师，我希望逐项控制史料和关键设计，清楚知道教学包是否满足门禁，并把确认后的内容导出用于进一步备课。

**教学包最小组成**：

1. 教学情境与中心问题；
2. 可编辑的 1～2 课时探究流程；
3. 仅含教师已批准史料的史料包及出处/加工/价值信息；
4. 学生任务单和分层支架；
5. 证据对齐量规；
6. 主张—证据关系摘要与审计摘要。

**验收规则**：

- 教师能对每张史料卡执行批准、退回修改、替换或排除；对问题、活动、支架和量规能够编辑并确认。
- 只有 MUST-008 无阻断项、所有拟导出史料均获教师批准、变更后受影响项均重新确认时，才能生成“可试教候选”教学包。
- 导出材料保留引文、来源、删节、翻译/释义、教学加工和 AI 内容的必要区分。
- “可试教候选”不等于已经试教、专家认证或可公开再分发；导出界面必须说明。
- 导出只向当前教师产生本地文件/副本；不自动公开、发信、分享链接或写入第三方平台。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 教师逐项批准后预览完整教学包；审计通过则导出一个无缺项、状态清楚的本地副本 |
| 失败 | 导出失败或格式生成失败时保留当前确认状态，明确失败，不产生看似成功的损坏文件 |
| 未登录 | 无账号用户可完成审阅和本地导出；界面明确任务关闭后不保证云端恢复 |
| 越权 | 不得导出另一任务的私有材料、未批准来源、内部失败日志或排除内容；不存在管理员批量导出入口 |
| 边界 | 零批准史料、待核验/阻断项、许可不允许复制的内容、超长材料、特殊字符或部分输出为空时，阻断或以链接/元数据安全替代并明确说明 |
| 重复 | 同一内容重复导出可生成一致副本并提示时间/版本；重复点击不触发外发、重复收费或静默改变批准状态 |
| 恢复 | 导出失败后可重试；教师修改后旧“可试教候选”状态失效，重审通过后再导出，不丢失可继续编辑内容 |

**隐私/费用/外部副作用**：导出不得含真实个人/学生数据、秘密、内部日志或未授权全文；教师对导出后保管负责，但产品需显示许可限制。格式生成的成本须计入任务用量；除教师主动下载外无外部副作用，任何分享/发布能力都属于范围变更。

### MUST-010 临时数据、任务隔离与清除

**用户故事**：作为无账号使用者，我希望知道内容保存到何时、能清除什么，并确信自己的上传不会出现在别人的任务里。

**验收规则**：

- 开始任务时清楚说明：无账号、内容仅用于当前任务临时处理、不承诺跨设备/长期保存、不得输入真实学生或敏感数据。
- 当前任务中的情境、输入、上传、卡片、教师编辑、批准和审计结果彼此关联，但与其他匿名任务隔离。
- 教师可以清除单项上传或整个当前任务；清除前显示影响范围，清除后不得在普通产品界面恢复或重新导出被清除内容。
- 当前匿名任务及其系统控制的上传/恢复副本，在教师主动清除时立即进入删除流程；若未主动清除，最迟在最后一次活动后 24 小时失效。后续技术设计只能缩短这一上限，不能擅自延长；第三方处理方自身的保留限制必须在启用前另行披露和审查。
- 任务错误、用量与质量记录不得包含完整提示词、上传正文、个人信息或秘密；只记录完成验证所需的去内容化事件。

| 场景 | 可验收行为 |
|---|---|
| 正常 | 当前任务内可继续编辑；另一新任务看不到其内容；教师可清除单项或全部并收到完成确认 |
| 失败 | 临时保存或清除失败时不谎报成功，限制继续处理并给出安全重试/退出路径 |
| 未登录 | 全部核心行为按匿名当前任务工作；不以隐式账号、设备指纹或联系信息替代登录 |
| 越权 | 更换任务标识、打开他人链接或构造输入都不能读取、修改、导出或清除另一任务内容 |
| 边界 | 浏览器/窗口关闭、并发打开、存储不可用、任务过期、超大上传或输入疑似敏感数据时，按最小化与拒绝规则处理并明确可恢复范围 |
| 重复 | 重复清除返回一致且不泄露对象是否曾属于他人；重复保存不生成跨任务副本或重复外部费用 |
| 恢复 | 瞬时失败后只恢复当前任务最近安全状态；用户已主动清除或超过最后活动 24 小时的内容不得通过普通恢复重新出现 |

**隐私/费用/外部副作用**：这是隐私与隔离门禁。不得把教师材料用于跨任务推荐、公开样例或未声明训练用途；不得记录设备指纹作为隐藏身份。清除/恢复不应产生付费外部调用；若临时处理涉及第三方 AI，后续设计必须披露传输、保留和删除限制。无消息、发布或第三方写入副作用。

## 8. 端到端状态与权限模型

### 8.1 任务状态

```text
草稿情境
→ 问题已确认
→ 史料核验中
→ 教学设计中
→ 待审计
→ 待教师批准
→ 可试教候选
```

任一上游事实变化都会使受影响的下游状态回退到“待复核”，而不是保留虚假的绿色通过状态。教师可以在当前任务内返回前一步；清除任务为终止状态。

### 8.2 v0.1 权限

v0.1 不设账号、角色或管理员后台。唯一交互角色是“当前匿名教师”。权限边界不是“任何人均可访问全部内容”，而是：

- 当前教师只能访问当前任务的临时内容。
- 新任务、另一访问者或构造的任务标识不能访问当前任务。
- 不存在跨任务检索私人上传、批量导出、后台查看、替他人批准或绕过审计的能力。
- 本地演示维护者的开发操作不属于产品用户功能，不能成为绕过产品门禁的公开入口。

若未来需要账号、分享、团队或持久项目库，必须退回章程与 PRD，重新设计身份、资源归属、保留/删除和越权场景。

## 9. 首个示范课程验收夹具

首个样例仅用于检验通用工作台，不把产品限定为唐史或高中产品。

| 项目 | 固定条件 |
|---|---|
| 教材 | 统编版《中外历史纲要（上）》 |
| 课次 | 第 6 课《从隋唐盛世到五代十国》 |
| 学情 | 重点高中高一普通班；主要困难是不会归纳、不能提炼材料观点，并可能混淆史料事实、史料观点和自己的解释 |
| 课时 | 1 课时，45 分钟 |
| 核心范围 | 只处理唐朝前期“盛世”的证据判断；五代十国仅作必要边界/延伸，不覆盖整课全部内容 |
| 中心问题 | “依据哪些史料，我们可以把唐朝前期称为‘盛世’？” |
| 核心活动 | 小组分析多类型史料，个人完成 120～150 字“盛世证据判定书” |
| 最低证据要求 | 使用至少两种类型史料；指出至少一项史料价值或局限；形成有边界的结论 |

样例必须证明：

1. 至少两种类型的公开候选史料完成精确来源与许可核验；在此之前只可使用占位元数据或合成材料，不把拟选史料写成已确认事实。
2. 学生必须区分材料信息、材料观点和自己的解释，并通过比较而非抄录形成判定。
3. 支架回应归纳与观点提炼困难，但不直接给出“盛世”答案。
4. 量规能区分“罗列史料”“解释史料如何支持主张”“互证并说明局限”“形成有边界结论”。
5. 45 分钟含阅读、讨论、个人产出和必要转场；超时即为审计阻断项。
6. 所有史料由教师批准，引用 100% 可解析到相符来源，伪造/错配为 0。

## 13. 停止、缩小与变更条件

### 13.1 立即阻断当前教学包

- 伪造、不存在、题名相似但引文不符或无法定位的来源可能进入可交付状态。
- 最终材料不能追到来源、版本/馆藏记录或加工链。
- 未核验许可的全文/图片准备进入 Git 或公开演示。
- 真实学生、未成年人、个人、敏感、秘密或无权材料进入处理、日志、测试或演示。
- 核心活动不用证据也能完成，或量规没有评价证据选择、解释、互证/质疑和结论边界。

### 13.2 缩小范围或停止 v0.1

- 无法在 12 周、每周 8 小时人类投入、¥200/月和总计 ¥600 内实现核心闭环。
- 无法招募 5 名同时覆盖初高中的历史教师提供近三个月真实任务。
- 核验流程没有降低总耗时/返工，或效率改善依赖跳过来源、版权、隐私和质量门禁。
- 学情适配最终只表现为缩短文字，不能改善阅读、归纳、比较和观点提炼。
- 可用方案必须依赖 LMS、巨大自建数据库、学生多角色、持久个人数据或高额付费服务才能成立。
- 教师只下载成品而不审查史料，M-04 明显失败，说明核心价值行为没有发生。

触发后先停止新增功能，记录证据并由用户决定缩小、转向或终止；AI 不得自行放宽门禁。

### 13.3 必须退回章程/PRD 的变更

- 加入学生端、账号、云端长期保存、分享、团队角色、管理员、支付、消息、定时任务或第三方写入。
- 使用真实学生/教师个人数据，或面向未成年人直接开放。
- 从非商业作品集/研究演示转为收费或学校正式服务。
- 把地方史变成唯一内容范围，或把产品从工作台改为纯聊天问答/通用内容生成器。
- 改变教师最终批准权、来源门禁、成本上限或公开发布边界。
