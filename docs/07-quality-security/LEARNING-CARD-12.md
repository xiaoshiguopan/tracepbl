# 阶段 12 学习卡（已批准归档）

日期：2026-09-05。

- **集成通过与安全通过不同**：原有用例都通过，仍可能漏掉“先备份、再删除、后恢复”的组合。审查必须从承诺出发设计反例。
- **恢复也是一次数据写入**：只检查数据库能否恢复不够，还要确认已经删除的内容不会回来。备份外的删除保护记录需要独立保留规则。
- **开关必须在执行端生效**：前端不显示按钮、API 不接新任务，都不能替代 Worker 停止真实调用的检查。
- **限额要在消费前预留**：费用已经发生后再拒绝结果，不能追回消费。生成和 embedding 的金额不能分开漏算。
- **安全测试不需要真秘密**：用自己新建的合成标记文件即可证明私有目录是否可读。检查不会触碰真实 key。
- **失败证据有价值**：先复现，再最小修复，再验证；环境超时、跳过项和未完成审查都要保留原样。

- **文件与数据库是两个提交点**：先写 pending 再提交 DB；只有两边一致才确认。未知状态要停下保留现场，不能猜测成功。
- **旧备份也会带回旧费用**：恢复后冻结真实调用 24h，防止当天额度被恢复操作重置。模拟演示不受影响。
- **读取上限要在读取过程中执行**：读完再判断太大，只能拒绝结果，不能避免读取时的资源消耗。
- **通过与未验证都要说清楚**：Linux Docker 恢复通过，不等于 Windows 原生恢复通过；缓存依赖镜像能启动，不等于 Docker Hub 全新拉取成功。
