# CP-12-01：删除恢复与费用边界补齐

日期：2026-09-05。状态：用户已明确回复“批准”，已完成设计细化、实施和合成复验，待本阶段验收。等级：C2。最早回到阶段 7 的相关数据设计，继而复核阶段 9；未受影响设计继续有效。批准不含归档或真实调用。

## 触发证据

1. **恢复后复活已删除任务（S12-01，High）**：隔离合成库中创建任务，`pg_dump -Fc` 保存删除前备份，原库到期 purge 返回 true、任务数为 0；将备份恢复至新空库，原任务 `deleted_at is null` 的计数为 1。现役 `restore.ps1` 只检查空库；`/health/ready` 只统计备份内 overdue 行。`0003` purge 删除任务关联审计，仅留不带任务标识的聚合事件，无法据此识别旧备份里应删除的任务。
2. **费用记账缺口（S12-06，真实调用启用前阻断）**：`handlers.ts` 的 embedding 结算固定 `actual_cny_micros=0`；`0003` generation 日金额只汇总 `usage_kind='generation'`；API 生成预留金额默认 0，价格完整性与预留上界未统一校验。结算时拒绝超额并不能撤回已发生的外部消费。当前 fake/disabled 无真实费用，本次没有真实调用。

## 建议的最小补齐范围

### A. 删除保护

- 新增 `0005`，不修改 0001—0004：以不含正文、标题、来源或学情的删除保护记录，保存任务不可逆摘要与到期时间；记录不随任务正文 purge 一同删除。
- 删除保护记录只供受控清理/恢复流程使用，不开放 UI、公共 API 或 Agent 操作权限。
- 对仓库外备份配套独立、可校验的最新删除清单；恢复先在隔离空库合并清单、清理到期任务与 checkpoint，再开放 API。清单缺失、过旧、校验失败或清理失败时拒绝开放，不能猜测“没有删除”。
- 明确保留规则：删除保护记录及清单随仍可恢复的备份保留；只有相关旧备份均已销毁才可由维护者显式清理。不得为方便恢复保存被删除的正文。
- 批准后先细化事务、清单持久化与崩溃顺序，并评审“清单写入失败、恢复旧备份、撤销删除、checkpoint 删除失败”组合状态，再实施；不能用仅有数据库内 tombstone 的实现冒充独立灾备保护。

### B. 费用保护

- 保持现有次数、Token 与 ¥2/日上限，不增加预算、不改模型。
- 真实生成和 embedding 使用同一明确版本的价格配置；缺 embedding 价格、缺保守预留或价格不一致时关闭真实执行。
- 在同一 workspace/日期锁内合计生成和 embedding 的金额预留；按实际使用结算。失败或结果未知保守占用额度，不因重试释放未知消费。
- 修改金额门禁通过新增向前 migration 完成；fake 继续明确零成本，CI 使用合成价格验证，无真实密钥或联网模型调用。
