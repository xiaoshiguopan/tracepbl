# CP-12-01 数据安全补齐规格

日期：2026-09-05；依据用户已批准 CP-12-01。此规格局部补充阶段 7/9，页面与权限主体不变。

## 删除保护与外部清单

新增 0005：`ops.recovery_control` 保存清单 epoch/初始化/维护状态；`ops.recovery_events` 以 identity 序号记录 SHA-256(workspace UUID + task UUID)、delete/restore、到期时间。无正文、标题、用户输入、来源或明文任务 ID，不依赖 task 外键，不随正文 purge 清除。运行角色只可读，记录由任务删除状态触发器追加；维护者保留原受控恢复权限。

清单放在数据库之外的持久目录，Compose 使用独立 recovery volume；不可放入源码或普通数据库 dump。记录随仍可恢复的旧备份保留。首次初始化仅允许新空库；已有历史任务的升级不能伪装成有完整删除历史，需由维护者核对当前活动库并显式执行 establish-baseline；该基线前的备份不可通过恢复门禁，必须新做备份。此操作不删除现有任务，也不把旧阶段备份视为可恢复。

删除与撤销的固定顺序：全局恢复事务锁 → 校验 DB 与清单一致 → 现有任务/幂等/24h 事务 → 将新记录作为 pending 清单原子写入并 fsync → 提交数据库 → 再校验并写 committed 清单。清单写失败则 DB 回滚；DB 已提交而最终清单未写时可凭完全相等的 DB 记录完成确认；无法判断提交结果的 pending 不自动丢弃、不伪造成功，阻止开放并保留证据。事务外未知失败不擅自撤销删除。

API 启动和受保护请求、Worker 清理都校验清单。读写使用同一数据库 advisory lock，避免把正常并发写清单当成损坏。恢复时必须提供独立核对的最新清单 SHA-256，不能从旧备份自己推断“最新”。哈希用于检测损坏/错文件，不对抗已控制本机且能同时篡改清单与预期指纹的攻击者。

恢复只向空库：校验 dump manifest/清单指纹 → restore/migrate → 验证备份内事件是外部已确认清单的前缀 → 进入维护状态 → 合并最新删除/撤销状态 → 先删到期 checkpoint 再 purge 正文 → 检查 overdue 为零且清单一致 → 离开维护状态。缺清单、pending、前缀不符、旧指纹、清理失败均不得开放；不读取生产/用户库来证明测试。

## 费用与重放

冻结每次任务的价格 JSON：mode、version、CNY、生成输入/输出和 embedding 单价（CNY/百万 Token）。fake 必须全为 0；real 必须均为正且 Worker 与冻结值一致。API/Worker 不使用客户端输入选择价格或提供商。

恢复或既有库建立新基线后，`real_ai_not_before` 至少推迟 24 小时，避免旧费用记录重置当日额度；fake 不受影响。

生成按最多两次的 24,000 输入/4,000 输出保守预留（真实模式最多 56,000 Token）；单次实际输入上界在调用前按 UTF-8 字节保守检查。每天生成 20 calls、生成/embedding 各 200,000 Token、合计 2,000,000 微元上限不变。金额由 PostgreSQL numeric 计算和同一 workspace/日期事务锁判定，生成与 embedding 同计金额。

新增 usage ledger 冻结价格与 started 标识；外部调用前以有效 job lease 原子认领使用权。已 started 的未知调用不重复执行，失败保留预留；已结算不重付。embedding 按整批保守上界预留、按实际 Token 结算。结算核对冻结价格和单次输入/输出上限，超额不能假成功，也不能以丢弃结果掩盖已消费。

## 组合状态评审

| 情形 | 必须结果 |
|---|---|
| 清单不可写 + 删除 | 回滚、内容保留，不给删除成功 |
| 清单 pending + DB commit 成功 | 只在 DB 事件完全相符时补确认 |
| 清单 pending + DB 状态未知 | 拒绝开放，保留现场 |
| 旧备份 + 后续删除 | 按最新清单隐藏/到期清除，不能复活 |
| 删除后在 24h 内撤销 | 新 restore 记录胜出；不把旧 delete 再应用 |
| checkpoint 清理失败 | 不 purge 正文、不开放；可幂等重试 |
| 并发生成 + embedding | 合计金额锁，超过上限的请求在调用前被拒绝 |
| 价格缺失/漂移 + 重试 | 不调用；冻结价格不能被新配置静默替换 |
| 已发起调用 + 崩溃重放 | started 阻止重复消费，未知额度不释放 |

不修改 0001—0004、不加入新生产依赖、不提高预算、不启用真实模型。向前修复，回退时关闭恢复/真实执行并保留删除保护记录。
