# 阶段 7 学习卡：数据库为什么不能照着页面画表

> 面向非数据库专业读者
> 日期：2026-09-03

## 一句话结论

页面描述“老师此刻看见什么”，数据库要保证“几个月后仍能证明当时用了哪份史料、谁改了什么、冲突和删除时不会串数据”。因此一张页面通常会跨多张表，一份前端状态也不能直接塞进一个大 JSON。

## 这次最重要的五个概念

### 1. 当前状态与历史版本是两回事

教师继续编辑时需要快速读写“当前稿”；签发、审计和导出需要不可变的“当时版本”。本方案同时保存可变 current row 和不可变 milestone revision。这样既不让每次按键都制造历史快照，也不会因后来编辑而改写已经签发的证据链。

### 2. 外键不只是连线，也是防串数据的护栏

每个 task 下的问题、史料选择、证据关系和活动都携带 workspace/task 作用域。复合外键让数据库自己拒绝“把 A 任务的证据接到 B 任务”。私有史料还有额外 scope guard；task ID 本身永远不是权限。

### 3. RAG 向量不是史料真相

原始来源版本和定位信息是真相；chunk 与 embedding 都能重建。向量只帮助找候选，不能证明史料真实、许可成立或引用准确。当前规模少于 10,000 chunks，精确 cosine 检索简单、可解释，没必要为了“看起来高级”先上近似索引。

### 4. 删除不是一条 SQL 就结束

教师点删除后任务立即不可见，24 小时内可撤销；到期后才清理 revision、关系、chunk、vector、job、checkpoint 等依赖。删除前后的状态、重试和残留都要测试。P11 仍然取消：删除入口可以在现有任务菜单，不需要恢复一整页“数据中心”。

### 5. 备份只有恢复成功才算备份

本地作品集项目不需要生产级高可用，但升级前必须 `pg_dump`，并定期在全新数据库执行 restore + 约束/检索/删除 smoke test。只有 dump 文件而从未恢复验证，不能声称可恢复。

## Demo 与完整工程

| 形态 | 数据放哪 | 是否调用 GLM | 面向谁 |
|---|---|---|---|
| GitHub Pages Demo | 访客自己的 IndexedDB | 否；只用预生成结果 | 招聘者随时点开体验 |
| 完整本地工程 | 本机 PostgreSQL | 有 key 时可手动调用；无 key 仍可运行 | 克隆仓库进行技术审阅 |

两者共享产品契约，但不共享运行时数据。Pages 不需要服务器、域名或秘密后端。

## 当前定下来的边界

- 一个本机 workspace、一个用户；不做登录、分享或 RLS。
- 只用公开、合成、明确非敏感的教师内容；绝不使用真实学生数据。
- 来源输入只含 URL 与文本；PDF/DOCX/OCR 摄取以后再决定。
- 生成用可替换 provider adapter，当前选 GLM；embedding 固定 `embedding-3` 1024 维。
- 模型、提示、来源、chunk、revision 都可追溯；密钥和完整模型日志不入库。
- 导出文件由浏览器即时生成，数据库只记导出事件，不保存二进制文件。

## 进入编码前还要发生什么

阶段 7 文档已获用户批准归档。归档完成后仍须用户另行明确开始阶段 8，才能编写 schema/migration/test，并用临时 PostgreSQL 验证约束、并发、删除和恢复。数据库文档获批不等于授权后端 API、真实 RAG 或模型调用。
