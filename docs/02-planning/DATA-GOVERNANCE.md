# 史证工坊数据治理规范

> 文档版本：0.2
> 更新日期：2026-09-03
> 状态：0.2 已批准归档
> 原则：当前只允许合成数据与许可明确的公开材料

## 1. 分类与准入

| 等级 | 示例 | 当前是否允许 | 处理规则 |
|---|---|---|---|
| G0 合成 | 虚构教师输入、人工构造状态/错误 | 允许 | 不得由真实个人数据改名而来 |
| G1 公开且许可明确 | 公版史料、明确开放许可元数据 | 允许，经记录 | 记录来源、版本、定位、许可和加工 |
| G2 公开可访问但复用权未知 | 网页、图片、OCR 文本 | 仅作候选链接/最小摘录 | 未核验前不得打包、全文复制或公开分发 |
| G3 一般个人数据 | 姓名、联系方式、教师未公开工作内容 | 当前禁止 | 未来须新批准、告知、最小化和删除机制 |
| G4 敏感/未成年人数据 | 学生身份、作业、成绩、健康等 | 禁止 | 不进入产品、Git、日志、测试、截图或模型 |
| G5 秘密 | Token、capability、Cookie、私钥、连接串 | 运行时必要时允许 | 仅秘密管理，禁止持久明文与外泄 |

公开可访问不等于允许复制、训练或再发布；许可不明确时状态必须是“待核验”。

## 2. 数据目的与最小化

| 数据域 | 目的 | 最小字段原则 | 真相源 |
|---|---|---|---|
| 任务背景/问题 | 建立探究目标 | 不收姓名、学校、班级 | 完整模式 PostgreSQL；Demo IndexedDB |
| 来源与版本 | 可追溯引用和许可判断 | URL/书目信息、定位、版本、权利状态 | PostgreSQL；公开 fixture 可版本化 |
| 论断/证据/活动/量规 | 构建课程方案 | 只存任务所需文本与关联 | PostgreSQL/IndexedDB |
| AI 运行元数据 | 重现、费用、故障诊断 | 模型/模板版本、用量、状态；避免原文全文 | PostgreSQL/结构化日志 |
| 审计记录 | 证明门禁和教师决定 | 事件、对象、前后状态、时间、关联ID | 追加式审计存储 |
| 切片/向量 | 检索派生数据 | 保持来源/版本外键，可从有权原文重建 | PostgreSQL pgvector |

未经明确用途的字段不采集；“以后也许有用”不是用途。

## 3. 生命周期

```text
授权/准入 -> 收集或生成 -> 校验/分类 -> 使用/派生 -> 教师审查
-> 导出（可选） -> 持续本地保存 -> 用户显式删除 -> 立即隐藏
-> 24小时撤销窗口 -> 彻底清除正文/关系/revision/切片/向量/job/checkpoint
```

- Pages Demo 数据只在当前浏览器 IndexedDB，生命周期由该浏览器和现有任务菜单控制，不宣称服务端删除或跨设备恢复。
- 完整本地模式未删除的任务持续保存；不再按最后活动时间自动过期。
- 用户显式删除后立即阻止普通访问；24 小时内允许明确撤销。到期后由幂等清理任务处理数据库正文、关系、revision、私有切片/向量、缓存、job 与 checkpoint 残留。
- 审计只保留证明彻底删除所需的最小非敏感墓碑信息；不得保留可重建内容、密钥或旧 capability。
- 导出包含来源/版本/定位、加工说明、许可状态、审核状态和生成时间；不包含密钥、内部日志或他人任务。

## 4. 合成与公开测试数据

- 每个 fixture 带稳定 ID、版本、分类、生成/来源说明、许可、用途和预期状态。
- 合成数据覆盖中文长文本、空值、边界、恶意输入、来源缺失、许可未知和冲突证据，但不得映射可识别真实个人。
- 公开史料只保存许可允许的范围；图片、全文或 OCR 是否可进入仓库逐项审核。链接失效时保留书目信息但不得伪造内容。
- 真实数据、生产导出、隐私信息和含其内容的截图不得进入 Git 历史；误入后立即停止、清理范围并按泄露事件处理。

## 5. 未来真实数据导入门禁

在阶段12质量与安全通过、数据来源/授权/隐私告知获批前，禁止真实数据。未来若提出导入，必须先完成：

1. 明确数据所有者、合法/授权依据、用途、字段、保留期和第三方传输；
2. 在隔离环境清洗、映射、去标识并备份，生成校验报告；
3. 用合成副本演练导入、冲突、回滚和删除；
4. 小批试导、数量/哈希/抽样核对，经用户批准后扩大；
5. 证明可导出、可删除、可恢复且日志不含禁止数据。

## 6. 第三方与跨边界传输

- 默认不把完整史料和教师输入发给模型；只发送完成步骤所需的最小片段，并记录提供商、模型、区域、保留/训练政策和用途。
- 未完成提供商数据保留、训练用途、跨境与删除能力复核前，只能使用合成/公开数据。
- 对象存储、数据库、模型和监控各用独立最小权限身份；不得因方便共享根凭据。
- 新第三方或数据用途变化属于重大变更，必须重新批准。

## 7. 备份、恢复与删除目标

Pages Demo 无服务端备份；用户可导出并自行保管。完整引擎在本地持久运行，采用手动逻辑备份：重要升级前执行 `pg_dump`，备份放在仓库外；CI 临时数据库在任务结束后销毁。

本地模式不承诺生产 SLA。备份只有在全新数据库完成 restore、约束/检索/删除 smoke test 后才算有效；恢复后必须重新应用已到期删除清单，避免复活已彻底删除内容。

若未来批准生产完整模式，启用前重新确认以下初始目标：

| 数据 | RPO目标 | RTO目标 | 说明 |
|---|---:|---:|---|
| 可重建公开来源目录/配置 | 24小时 | 8小时 | 版本化配置优先恢复 |
| 本地 workspace/task | 用户每次重要升级前手动备份 | 尽力恢复，无生产承诺 | 不保证恢复最后一次 dump 后的编辑 |
| 已过删除宽限的任务 | 不恢复 | 删除优先 | 恢复流程必须重新应用 purge 清单 |

备份必须加密、与运行凭据分离、限制保留并至少在发布前完成一次恢复演练；没有恢复证据不能宣称备份有效。

## 8. 运维访问与审计

- v0.1 没有管理后台。维护者通过平台受控身份执行必要运维，使用最小权限、短时凭据和可审计记录。
- 生产数据查询默认拒绝；紧急访问记录原因、范围、批准者、命令/动作摘要和结束时间，不复制内容到本机或工单。
- 关键审计事件包括任务创建/访问失败、状态回退、来源/许可变更、AI/工具调用、教师批准/退回、导出、取消、删除、限额触发、运维访问和配置变更。
- 审计日志防止普通应用角色修改，保留期在生产设计时依据隐私与调查需要重新批准。

## 9. 验证证据

数据库阶段必须提供约束、workspace/task 隔离、迁移、删除宽限、级联清理和恢复演练；后端阶段提供授权、purge、日志脱敏和第三方最小传输测试；发布前以仅合成数据执行端到端删除并检查数据库、向量、缓存、队列、checkpoint 和日志残留。
