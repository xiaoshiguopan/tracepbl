# 史证工坊变更控制

> 文档版本：0.1
> 更新日期：2026-08-31
> 状态：已批准归档

## 1. 原则

批准后的范围、架构、契约、数据、权限、费用、部署和验收标准不能在编码中静默改变。发现新事实时先保留安全状态、记录提案和影响，再由用户决定；“实现更方便”不是越过阶段门禁的理由。

## 2. 变更提案最小内容

每项提案必须包含：

- 变更编号、日期、提出原因和新证据；
- 现状、拟议变化、明确不变化的内容；
- 受影响的需求 ID、用户流程、数据、权限、信任边界、契约、测试、费用和进度；
- 安全/迁移/锁定/回滚风险，替代方案与“不改”的后果；
- 需退回的最早阶段、待重做证据、文件清单和最终批准者。

批准结果为：接受、拒绝、缩小范围或延期；口头讨论未形成明确批准时仍按未批准处理。

## 3. 影响等级与审批

| 等级 | 例子 | 处理 |
|---|---|---|
| C0 澄清 | 不改变行为的错字、链接、措辞一致性 | 当前阶段修正并记录差异 |
| C1 局部 | 已批准设计内的实现细节，不改变公共契约/数据/权限 | 当前阶段评审，补测试与文档 |
| C2 跨层 | 公共契约、状态机、字段、交互主链、依赖或运行方式变化 | 停止受影响实现，退回对应设计并获用户批准 |
| C3 重大 | 范围、用户、真实数据、权限模型、唯一技术栈、部署、费用上限或外部副作用变化 | 退回规划；必要时退回立项/技术选型，重新研究和明确批准 |

任何真实数据、付费、Public、push、部署、域名购买或第三方外发，即使技术上是 C1，也需要独立明确授权。

## 4. 必须退回哪一阶段

| 变化 | 最早返回点 |
|---|---|
| 导航、页面职责、组件状态、无障碍交互、Demo 说明 | 阶段5 前端设计 |
| 实体、关系、字段语义、保留/删除、索引、事务、RLS取舍 | 阶段7 数据库设计；若影响前端则先回阶段5 |
| API、错误、授权、队列、AI/RAG/Agent 工具、限额 | 阶段9 后端设计；若契约影响前端/数据则回更早层 |
| 用户、核心问题、MUST/NFR、公开形态、技术栈、预算上限 | 阶段1、2或4中最早受影响阶段 |
| 只修复与批准意图不符的缺陷 | 当前实现阶段；若文档本身含糊则先回设计 |

返回较早阶段后，所有下游受影响批准状态改为“待复核”；未受影响部分可保留，但必须列出依据。

## 5. 实施、迁移与复验

1. 在 `PROJECT-STATE.md` 记录已批准变更和允许路径；
2. 先更新权威设计/契约，再更新实现，禁止代码先行后补设计；
3. 对数据/公共契约提供兼容窗口、迁移与回滚/前滚路径；
4. 运行直接受影响测试，再运行跨层、回归、安全和构建门禁；
5. 更新手册、README、测试图、变量/权限/数据说明和阶段报告；
6. 用户批准归档后才提交，公开动作另行授权。

## 6. 紧急安全处置

密钥泄露、越权、数据暴露或失控费用可先采取可逆的安全动作：撤销密钥、暂停入口/Worker、关闭发布或限制流量。不得借紧急处置扩大功能。稳定后补齐事件记录、根因、数据影响、恢复验证和正式变更批准。

## 7. 追踪和防止静默漂移

- 需求 ID → 设计 → 契约/迁移 → 代码 → 测试 → 发布证据保持双向链接。
- 阶段结束比较批准文档、实际差异和运行行为；不一致即缺陷或未批准变更。
- 依赖升级、模型版本、提供商政策和 GitHub/浏览器运行变化按风险定期复核；自动升级不得越过测试与批准。
- 临时开关有所有者、默认值、清理条件和截止阶段；不能成为永久双架构。
