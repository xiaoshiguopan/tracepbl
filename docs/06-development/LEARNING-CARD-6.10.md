# 学习卡：阶段 6.10 P08“设计检查”

> 日期：2026-09-02

## 本轮学到什么

1. 教师需要的是“哪些地方会影响这节课”，不是先点一次按钮再观看系统工作。把确定性结果直接呈现、收起通过项，能显著减少机械等待和无意义操作。
2. 检查页的核心不是更多状态徽章，而是从问题、史料、论证、活动到量规的一条证据链。连续长卷和竖向证明线比仪表盘更符合本项目的阅读任务。
3. “教师确认”不应从空白理由开始。先给一个有依据的首选处理，再让教师修改理由，既保留教师责任，也减少把流程做成考试题的感觉。
4. 前端确定性规则只能帮助体验。阻断、未知、权限和未来服务端授权必须分开表达，尤其不能因为字段齐全或样式变绿就宣称安全、准确或可交付。

## 实现中暴露的问题

- 最初校验失败状态虽然能显示错误，但侧栏错误地写成“0 项待确认”，且组合选择器会把焦点落到整条发现而非 textarea。现已改为“完善教师确认理由”，并按阻断 → 无效字段 → 待确认项的明确优先级聚焦。
- P07 的下一步说明仍写着“设计检查尚未实现”。真实导航接通后同步移除，避免相邻页面与运行态互相矛盾。
- 原规划把教师最终确认和导出拆成 P09/P10 两页。用户确认合并后，现役页面规格、状态矩阵、用户流程、组件职责和数据契约必须一起改，不能只改步骤名称。

## 后续约束

- P09 继续执行“讨论方案 → 生成页面图 → 用户确认 → 编码”，并以 P01 视觉母版为基线。
- P09 必须在同一页完成最终确认、权利替代预览、格式/文件名和本机生成；不得恢复独立 P10 路由或第二套确认状态。
- 当前 P08 fixture 只验证交互。未来真实检查需要权威来源、结构化结果、可追溯规则/模型版本和服务端授权，未知永远不能自动变成通过。
