# 阶段 10 学习卡：后端为什么不是“给页面接个接口”

> 日期：2026-09-04

这一阶段把阶段 9 的设计变成了可运行的 API、Worker、RAG/AI 边界和本地数据库协作方式，但没有把 GitHub Pages Demo 接入秘密后端。

- **API** 像前台窗口：检查会话、输入、版本和权限，快速保存或排队，不在一次网页请求里等待 AI。
- **Worker** 像后台办事员：从 PostgreSQL job table 认领任务，持有有期限的“租约”。旧 Worker 即使醒来，也不能凭过期租约覆盖新结果。
- **事务** 像一次不可拆的记账：保存内容、增加版本、写审计和幂等回执要么一起成功，要么一起不发生。
- **RAG** 不是“让 AI 自己找答案”：它只从当前 task 已选择且权利允许的准确 source version/chunk 中检索，并逐条核对引用。
- **Agent** 只编排“冻结输入 → 检索 → 生成一次 → 校验 → 等教师决定”。权限、删除、费用、引用门禁和批准仍由普通代码与数据库决定。

常见坑：task ID 只能定位，不能授权；前端隐藏按钮也不能授权。另一个坑是把 AI 输出直接写成当前教案——本项目先保存不可变 generated revision，教师明确采用后才更新当前状态。

你可以亲自检查：在没有任何 GLM Key 时运行本地后端并访问 `/api/v1/runtime`，应看到 `ai.available=false`；同时普通任务与手工保存仍可工作，AI 操作会明确失败而不会静默换模型。
