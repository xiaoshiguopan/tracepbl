# 阶段 8 学习卡：数据库代码真正保护了什么

> 日期：2026-09-03

数据库实现不是把页面内容“存进去”就结束。本轮最关键的成果，是让错误关系即使绕过前端也无法落库。

- 把任务 A 的私有材料选给任务 B，会由数据库拒绝；task ID 仍不是权限。
- 两个窗口同时保存同一版本，只有第一个能成功；旧写入不会覆盖新写入。
- 删除必须同时带准确的 24 小时清理时间，普通查询立刻看不到；hard purge 会删除任务私有子树而保留公共目录。
- 没有复制权或没有正文的来源不能生成 chunk；向量只能依附准确 source version。
- app/worker 不是数据库 owner：app 不能改历史 source version，worker 不能伪造教师决定，两者都不能改 schema。
- 向量检索目前是 1024 维精确 cosine。没有为了“看起来高级”预建近似索引。

备份也做了真实恢复：custom dump 恢复到全新 PostgreSQL 后，表 owner、迁移记录、任务和 embedding 数量一致。只有这一步成功后，才称得上“备份可恢复”。

`agent` schema 目前是空的隔离舱，不是假装已经实现 Agent。LangGraph 官方 checkpointer 要等后端实现阶段由固定版本迁移创建，避免猜测第三方内部表。
