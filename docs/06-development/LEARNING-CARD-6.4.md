# 阶段 6.4 学习卡：电影不是浏览器特效的同义词

## 1. 为什么删除实时 3D

技术原型证明 WebGL 可以运行，不等于它能提供电影质感。用户需要的是摄影、角色表演、材质、灯光和剪辑；继续给低模空间叠纸片、粒子和鼠标光点，只会增加代码与廉价感。因此正式路径改为预渲染影片，浏览器只负责稳定播放、回退和真实 UI。

## 2. 为什么没有用 CSS 冒充成片

静态图缩放、景深滤镜和图片轮播能制造“在动”，但不能制造可信的角色动作、空间位移和镜头揭示。它们会让 Demo 看似暂时完成，却把返工推迟到更昂贵的阶段。本轮宁可明确影片资产尚缺，也不伪造完成证据。

## 3. 为什么衔接只保留匹配剪辑

页面衔接的职责是保持空间连续，不是另演一段动画。影片尾帧让实体纸面占满画幅，P01 用同源但低眩光的工作面接续；路由立即切换，不再增加独立 UI 过渡。飞行白纸、门户光圈和大面积白洗都已删除。

## 4. 为什么最终交付叫“史料包”，但 P01 不问它

教师真正需要的不是系统内部的“证据判定书”或抽象“产物类型”，而是一组能核验、能定位、能合法使用、能直接带进课堂的材料。但这不是 P01 需要教师选择的字段：P01 只确认课程边界，正式问题归 P02，史料用途与组成归 P03，阅读难度归 P06；“史料包”是闭环逐步形成的交付结果。

## 5. 为什么没有引入新前端库

React、原生表单、IndexedDB、History API 和 CSS 已足够承担 P00/P01 的 UI。新增 3D、动画、表单、路由或状态库不会提高审美，只会扩大维护面。

## 6. 为什么工作台不是纯白，也不是全暗

教师需要长时间阅读中文史料。纯白卡片会抬高总亮度，全暗正文又容易出现光晕和扫描件亮度反差；因此工作台采用深色低干扰框架包围中低亮度、无纹理阅读面。历史氛围停留在外围和材料关系中，正文背后不出现纸纹、壁画或灯光。

## 7. 为什么最终删除三幕而不重写数据层

三幕虽然比字段堆叠更有秩序，但仍迫使教师在第一步提前回答后续决策。最终页面删除页签，只保留当前必要字段；底层仍复用同一份 draft、校验和 IndexedDB，旧草稿可以兼容，后续页面也能按需读取已有值，不为 UX 返修复制业务状态。

## 8. 当前应怎样审阅

当前页面已经接入真实的 MiniMax H3 预渲染影片，可以审阅镜头速度、洞窟揭示、纸面收束、标题叠放、一次点击以及 P01 视觉连续性。应把“页面强制静音”和“文件物理无音轨”分开验收：前者已经通过，后者仍需无损移除 AAC 轨道。

## 9. 为什么采用 H3 V2 首尾帧

旧版 Hailuo 2.3 文档不是当前最新能力。MiniMax H3 V2 同时支持首帧和尾帧、4—15 秒与 2K 输出，恰好把“从王圆箓肩后进入”与“落到工作台纸面”两个不可妥协的构图锁在同一条连续镜头中。API 只用于离线制作静态影片资产，网页运行时不连接 MiniMax，也不持有密钥。

## 10. 为什么首页改为下三分之一信息轨

电影感不是把标题放得最大，也不是把按钮做成发光卡片。画面已经承担叙事，UI 的职责是建立清楚的观看秩序：标题回答“为什么进入”，用途说明回答“这是什么”，入口回答“下一步做什么”。三者共用一条底部基线后，视觉重量有连续的去向；透明文字入口也不再与影片争夺注意力。

## 11. 为什么只引入标题所需字体切片

Windows 系统宋体回退会使不同机器上的标题气质漂移，但加载完整中文字体会给首屏增加数 MB。当前使用 Google Fonts 官方 Noto Serif SC unicode-range 文件，只声明标题命中的六个切片并本地托管，共 235,124B。它让关键标题稳定，同时不把字体技术扩散到正文、表单或新的依赖体系。

## 12. 为什么摘要不需要“生成”

教学情境摘要只是教师刚填写内容的另一种排列表达，不产生新的知识，也不需要系统推理。为它设置“生成”会制造虚假等待，并迫使教师对同一批信息确认两次。现在摘要随输入即时更新，P01 只保留一次真实确认。

## 13. 为什么不在第一页问完整备课条件

字段只有在答案会改变紧接着的决策时才应出现。P01 下一步是收束探究问题，因此只需要课程边界；史料用途和数量在开始查找时才有价值，阅读困难和前置知识在设计活动与支架时才有价值。按需渐进收集既减少填写成本，也避免隐藏字段造成用户看不见的校验失败。
