# 阶段 6.2 学习卡

## 1. 这一步做了什么

我们没有直接制作昂贵的电影级素材，而是先用很轻的几何占位回答工程问题：浏览器能否延迟加载 3D、镜头能否在 6.5 秒内推进、主页面是否始终可用、手机和失败设备能否自动退出 3D，以及退出后是否干净释放资源。

## 2. 为什么技术原型看起来不够“高级”

这一版故意不承担最终审美验收。若先把时间花在人物、壁画和光影细节上，却后来发现包体、帧率或无障碍方案不成立，返工成本最高。现在已经证明“容器和逃生通道”成立；下一门才把预算投入王圆箓、藏经洞、残卷转场和环境声的最终表现。

## 3. 六个关键概念

1. **动态加载**：3D 代码不进入首屏主包，只有合适设备才下载。
2. **四级降级**：完整 3D、轻量动态、静态终帧、纯色安全层共享同一条主流程。
3. **首帧不阻塞**：标题和按钮先显示，3D 后增强；加载失败不会白屏。
4. **context loss**：显卡上下文可能被系统回收；原型会释放 3D 并回到静态层。
5. **资源释放**：不再使用时停止循环、移除监听并释放几何、材质和 renderer。
6. **一次性性能样本**：只在前两秒记录帧率和场景复杂度，不让监控本身持续拖慢 React。

## 4. 当前数字如何理解

首帧 116ms、174fps 是这台机器、这个低模场景的一次样本，不是对所有教师电脑的承诺。更可靠的结论是：入口主包和 Three chunk 在批准预算内，低于 24fps 会自动降级，手机默认不显示完整 Canvas。

## 5. 你可以亲手检查

本地运行 `npm run dev`，打开 `/tracepbl/?p00-mode=full&p00-intro=replay` 可以重看序章；打开 `?p00-mode=safe` 可看最保守层。技术状态条故意保留“技术原型”和“音频待最终资产”，避免把占位效果误认为完成品。

## 6. 下一步看什么

批准归档后进入最终视觉门：重点不是继续堆几何，而是以用户已确认的“动画风格高级 CG、王圆箓提灯进入藏经洞、残卷转为明亮工作台”为目标，制作或选定有来源记录的最终资产，并重新测包体、性能、手机、减少动态和声音体验。
