# 阶段 6.3 学习卡

## 1. 这一步真正完成了什么

技术原型只证明“3D 能不能安全运行”；这一步才决定用户第一眼看到什么。最终方案没有让浏览器实时绘制复杂人物，而是把电影级人物、洞窟和经卷做成针对桌面/手机的预渲染画面，再让 Three 只负责轻微光尘、灯火和空间视差。

这样既保留了沉浸感，也避免教师电脑必须实时渲染高成本角色。

## 2. 为什么不是一张图铺到底

桌面构图需要左侧留标题，手机构图需要上方保留人物、下方留阅读区。直接裁切同一张横图会切掉王圆箓或让文字压在高亮细节上，所以两种视口使用不同构图，而不是只靠 CSS 硬裁。

## 3. 为什么画面不能出现“像字的纹理”

AI 很容易在经卷、印章和壁面上生成似是而非的字。历史产品尤其不能让这些视觉噪声被误认为史料。本次首个方向图和手机首稿都因疑似伪文字被拒绝；最终图只保留空白残卷和抽象原创纹样，并常驻艺术声明。

## 4. 声音为什么显示“开”却可能先听不到

现代浏览器通常会拦截未经互动的自动播放。产品默认保存“愿意开启”的偏好，但不会用弹窗或阻塞层强迫播放；用户第一次点击或按键后再尝试。声音关闭后立即暂停，再开启会利用当前手势直接播放。

## 5. 四级体验不是四个页面

完整 3D、轻量动态、静态终帧和纯色安全层共享同一标题、按钮、演示边界与艺术声明。变化的只是装饰表现，所以显卡失败、手机省流、减少动态或图片失败都不会阻止教师进入任务。

## 6. 你可以亲手检查

本地页面已在 Codex 浏览器中保留。普通地址看最终体验；加 `?p00-mode=static` 看静态终帧；加 `?p00-mode=safe` 看纯色安全层；加 `?p00-mode=full&p00-intro=replay` 重看 6.5 秒序章。
