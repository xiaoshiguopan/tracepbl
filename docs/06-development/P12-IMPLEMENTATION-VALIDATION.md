# P12“任务不可用”实现验证

> 日期：2026-09-03
> 范围：阶段 6.12，仅 P12、P11 取消决策和必要现役前端契约同步

## 1. 已确认设计合同

- 用户明确取消 P11，并确认 P12“安全落页”效果图后授权编码。
- 页面延续 P01 的冷石色、宋体标题、矿物青动作色、细线与双栏纸面秩序；用大面积“留白封存页”表达内容被保护性隐藏，不使用红色报错卡、登录墙或仪表盘。
- 页面不显示证据脉络、任务标题、所有者、任务 ID 或具体失败原因；`expired`、`cleared`、`unavailable` 与未知原因在视觉上保持等价。
- 唯一主动作是“新建演示任务”，次动作是“返回演示说明”。标题加载后获得程序焦点，主次动作均可键盘触发。

## 2. 实现与边界

- 新增公开路由 `/task-unavailable`，并复用现有 `TaskUnavailable` 作为所有现役页面不可用状态的统一表现，不新增页面框架或依赖。
- 路由只按 pathname 识别；查询参数不会进入页面文案。未知 `reason` 或其他参数被安全忽略。
- 新建演示任务进入已知公开 fixture 的 P01；返回演示说明进入 P00。P12 不读取 IndexedDB 或任何任务对象。
- P11 没有 route、page、store 或清除组件。当前版本缺少应用内查看/清除本机任务数据能力，P12 不宣称数据已清除。
- 前端隐藏与统一文案只改善体验，不是真实授权；未来完整模式仍需服务端把不存在、过期和无权访问统一强制为不泄露结果。

## 3. 自动化与真实浏览器证据

- 聚焦测试先因缺少 P12 文案与路由产生 2 项预期失败，实施后通过。
- Vitest 验证安全文案、两个出口、无对象字段和未知参数等价路由。
- Codex 应用内 Chromium 验证 `/task-unavailable`、未知参数、P01 导航、P00 返回、标题焦点、首个 Tab 到主动作和控制台无 warning/error。
- 1440×900、390×844 与 320×800 均无横向溢出；可见按钮最低 44px；页面无音频。
- TypeScript、ESLint、Vitest（9 文件、46 项）、production build、生产依赖审计和 `git diff --check` 的最终证据见 `STAGE-6.12-REPORT.md`。
- production build 转换 47 个模块；初始 JS 205.23kB/64.58kB gzip，CSS 75.39kB/13.05kB gzip。

## 4. 未完成验证与风险

- P11 由用户明确取消，因此 MUST-010 中应用内主动查看/清除本机任务数据的部分未满足；用户目前只能使用浏览器自身的数据管理能力。
- 当前路由与界面不构成真实授权或隔离证明；服务端授权仍属于后续阶段。
- NVDA/VoiceOver、200%/400% 缩放、高对比及 Safari/Firefox 留待发布前设备矩阵。
