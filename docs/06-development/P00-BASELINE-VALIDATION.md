# P00 安全首屏验证记录

> 验证日期：2026-09-01
> 对象：阶段 6.1 静态安全首屏
> 结论：基座通过；不构成混合 3D 技术原型或最终视觉验收

## 1. 验证环境

- Windows 11，Node 24.19.0，npm 11.17.0。
- 应用：Vite 8.2.2 本地开发服务器，`http://127.0.0.1:5173/tracepbl/`。
- 浏览器：Codex 应用内 Chromium；无登录、无外网请求、无真实数据。
- Playwright CLI 先行尝试失败，原因是其 Linux 环境没有 Chrome distribution。没有执行浏览器下载，随后改用机器已有应用内浏览器。

## 3. 桌面浏览器验证

首帧可见品牌、作品集演示模式、环境声开关、年份与地点、唯一 H1、主动作、演示边界入口和艺术化演绎标签。装饰性的洞窟、人物、灯火与经卷结构不进入可访问树。

交互结果：

- 点击“开始证据探究”，边界说明出现，主按钮与次按钮均更新为展开状态；没有伪造任务或请求后端。
- 点击声音控制，按钮名称从“环境声：开”变为“环境声：关”，pressed 状态同步更新。
- 控制台 warning/error 数量均为 0。

## 4. 320px 窄屏验证

浏览器视口设为 320×800 后：

- `documentElement.scrollWidth - innerWidth = 0`，没有横向溢出。
- 环境声、主动作、边界按钮高度依次为 44px、47px、44px，达到触控目标底线。
- 两个主操作改为整行排列；标题、说明和艺术边界未被装饰遮挡。
- 洞窟视觉退到内容之后，场景说明隐藏，不损失主任务信息。

## 5. 键盘、焦点与动效

- 聚焦按钮的浏览器计算样式为 `3px solid #a995ff`，`outline-offset: 4px`；焦点不只依靠颜色微变。
- 主动作与声音控制使用原生 `button`，跳转主内容使用原生锚点；DOM 快照存在清晰角色与名称。
- 浏览器控制层未能可靠推进完整 Tab 顺序，因此完整键盘遍历标记为后续浏览器矩阵项，不伪称已测。
- CSS 动画只位于 `@media (prefers-reduced-motion: no-preference)` 内；减少动态用户不会进入呼吸灯与证据线动画。
- `forced-colors: active` 时隐藏纯装饰洞窟，并为三个按钮恢复系统可辨认边框。该条件本轮为代码复核，尚未在真实高对比模式模拟。

## 6. 降级与失败边界

- 当前无图片、视频、音频、WebGL、在线 AI、数据库或网络数据请求；因此媒体加载失败无法破坏标题、说明或按钮。
- 当前环境声按钮只保存本页 UI 偏好，不播放虚假音轨。
- 真实 3D/GPU/解码/音频失败、加载超时与静态终帧切换属于下一子阶段技术原型验证。

## 7. 发现与修正

1. 首轮浏览器检查发现主动作是无处理函数按钮；已修正为展开既定演示边界。
2. 清单中的 React 类型包原写为 `latest`；已改为已安装的精确版本，保持安装可复现。
3. 首次类型检查发现 CSS side-effect import 缺少 Vite 声明；已加入 `vite/client` 类型后通过。
4. 首次 lint 出现根包 ESM 警告；已声明根包 `type: module` 后无警告。

## 8. 原型判断

本轮证明的是“P00 静态安全层能运行、能降级、能被理解”，不是“3D 方案已可行”。下一原型必须另行验证预渲染主镜头、实时空间增强、首次/重看、5—7 秒非阻塞转场、极轻声音、四级降级、移动端与资源预算，并先通过运行时依赖准入。
