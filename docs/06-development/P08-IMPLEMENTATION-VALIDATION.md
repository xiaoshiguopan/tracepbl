# P08“设计检查”实现验证

> 日期：2026-09-02
> 范围：阶段 6.10，仅 P08、P07 相邻导航及已确认后续流程规划同步

## 1. 已确认设计合同

- 用户认可“异常优先的审校长卷 + 检查校样”方案，确认桌面效果图后授权编码。
- 页面延续 P01 的灰绿色画布、米白纸面、宋体标题、矿物青操作色与克制细线；主视觉是一张连续校样，不是卡片墙、仪表盘或普通大表单。
- 教师进入页面就看到检查结果，不先执行没有决策价值的“运行审计”。通过项默认收起，只突出真正影响课堂使用的阻断、未知、教师确认和建议。
- 用户随后确认最终确认与导出合并为一个页面；当前只同步后续规划和导航名称，没有实现 P09/P10 能力。
- 效果图只用于用户确认，没有复制进仓库或作为史料。

## 2. 数据、规则与恢复

- 默认确定性 fixture 共 18 项：16 项通过、1 项教师确认、1 项建议、0 阻断。它只验证前端任务流，不冒充实时 AI、外部链接检查或安全审计。
- 六类检查覆盖来源完整性、加工透明度、证据充分性、课堂可行性、活动—评价一致性、数据与范围。
- 首选处理为“保留证据缺口并限制结论边界”；采用后自动填入可编辑确认理由，避免让教师从空白 textarea 开始。理由少于 10 字或超过 500 字时不能完成，并聚焦具体字段。
- 阻断、未知、失败、超时和离线外部项均不能忽略或计为通过。建议项不阻断完成，但始终保留精确上游入口。
- IndexedDB 升至版本 7，新增独立 P08 草稿 store。问题、史料、论证、活动或量规变化通过类别快照只使相关检查失效，其他已知结果与教师处理保留。
- P07 确认成功后进入 P08；P08 可清洁返回 P01—P07。主证据流程现为 8 步，最后一步显示“最终确认与导出”。

## 3. 真实浏览器证据

使用本机 Microsoft Edge Chromium（Playwright CLI）验证：

- `http://127.0.0.1:5173/tracepbl/tasks/demo-tang-45m/audit` 返回 HTTP 200，显示 18/0/1/1/16 的默认校样。
- “采用建议”后理由自动填入，待确认变为 0、通过变为 17，主动作变为“完成设计检查”；完成后出现持久文本反馈，不伪造 P09 已实现。
- 校验场景显示 10—500 字错误；点击“完善教师确认理由”后，程序焦点落到 `aria-invalid=true` 的 textarea。
- 加载、空、缺上游、系统失败、30 秒超时、离线、不可用、阻断、上游失效和成功状态均有独立可观察结果；失败/超时/离线带未知项，阻断没有忽略入口。
- P07“确认评价量规”真实导航到 P08；P08“返回评价量规”真实回到 P07。
- 1440×1100、390×844 和 320×800 均无主页面横向溢出；390/320 可见交互目标没有低于 44px，窄屏把检查校样放在长卷之前。
- 首个 Tab 焦点为“跳至主要内容”，焦点环为 2.4px 实线；控制台 0 error、0 warning，仅有 React 开发提示；页面无音频。
