# 阶段 6.1 学习卡

## 1. 这一步做了什么

我们先搭好了网页的“地基”和“逃生通道”：即使未来的 3D、视频、声音或网络完全失败，用户仍能看到史证工坊是什么、知道这是 Demo、读到艺术与史料边界，并能操作主要按钮。

## 2. 为什么不直接做华丽 3D

电影感是增强层，入口可用性是基础层。先证明静态安全层在 320px 手机、键盘焦点和生产构建中成立，后面才能放心叠加 3D；否则最昂贵的视觉层一失败，整个产品入口也会一起消失。

## 3. 五个关键概念

1. **workspace**：一个仓库管理多个应用或包；现在只有 `apps/web`，没有提前创建空架构。
2. **production build**：把开发代码转换成可发布静态文件；它成功不等于全部体验已经完成。
3. **安全首屏**：不依赖媒体、网络或后端也能显示核心信息和动作的基础界面。
4. **渐进增强**：先保证基本能力，再添加 3D、视差和声音；增强失败时回到同一条主链。
5. **可访问语义**：按钮名称、开关状态、展开关系和焦点轮廓能被键盘及辅助技术理解。

## 4. 最容易踩的坑

- 只看到页面漂亮，就认为按钮真的能用。本次真实浏览器复核因此补上了主动作行为。
- 在依赖清单写 `latest`，导致别人以后安装到不同版本。本次把类型包固定为当前精确版本。
- 为做浏览器测试临时下载新运行时。本次在 CLI 缺 Chrome 时停止下载，改用机器已有浏览器。
- 把 CSS 洞窟剪影当作最终视觉。本版本只证明安全基座与视觉方向，后续仍有技术原型门和最终视觉门。

## 5. 你可以亲手检查

运行 `npm run dev`，打开终端给出的本地地址，把窗口缩窄到约 320px。检查标题是否完整、两个主按钮是否整行可点、环境声按钮是否仍可见，以及点击“开始证据探究”后是否出现“演示与数据边界”。

## 6. 下一步看什么

批准归档后才进入混合 3D 技术原型。那一步首先回答性能、加载、降级和依赖是否可接受，不会把几何占位或低清资产当作最终效果。
