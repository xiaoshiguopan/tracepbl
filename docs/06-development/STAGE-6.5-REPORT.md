## 1. 门禁与返修决策

- 阶段 6.4 已由提交 `5850d8c feat(web): complete P00 and P01 experience` 批准归档；P02 开工门禁成立。
- 初版实现完成后，用户否决“重复输入 + 诊断按钮 + 三段长表单”和不可返回的步骤栏，并采纳“自动承接 P01、直接给首选成果、只问关键选择、按需修改一句、已完成步骤可返回”的推荐方案。
- 第二轮体验复核中，用户进一步要求“只查看时自由切换、实际修改后才确认”，并否决突兀的“先看成果”提示和普通表单观感；交互改为当前位置与已到达进度分离。
- 第三轮视觉复核中，用户否决问题批注笺成品，要求以已批准的 P01 教学情境页为模板，先出高保真页面图、确认后再编码。用户确认“双栏纸张工作卡 + 即时摘要”效果图，并要求 P03 及后续页面都先讨论、出图、确认，再编码；后续页同样以 P01 为视觉母版。本轮没有提前实现 P03。
- 本轮重构仍满足阶段 5 的 P02 最小合同：类型及理由可纠正、至少一项有限建议、中心问题与学生证据产物由教师确认；没有退回数据库或后端设计。

## 2. 完成结果

1. P01 一次确认后直接进入 P02；P02 自动读取教材、课次、分钟和初步方向，不要求重复粘贴，也没有“诊断这个输入”按钮。
2. P02 直接复用 P01 的 `context-columns`、`form-section`、`brief-panel`、选择卡片和主按钮：左侧只确认问题类型、课堂侧重与中心问题，右侧即时摘要展示中心问题、学生证据任务和课堂边界。
3. 输入类型压缩为一行可纠正理解；只有会改变方案的重点选择出现，当前示范课提供“判断是否成立 / 比较不同群体或史料视角”。
4. 默认突出一份方案；选择另一角度会更新同一方案，不并排堆叠多张建议卡。中心问题默认以字段形态阅读，点击“修改中心问题”才进入编辑；系统派生的证据任务与范围不转嫁为默认输入。
5. “盛世”示范方向不会原样复述，而会收束为多类型史料比较、支持依据与限定条件；建议明确为预生成合成内容，不是史料或实时 AI。
6. “当前查看页”和“已到达进度”相互独立：从 P02 返回 P01 只查看时，可从 rail 或页面主动作直接回 P02；有实际修改时，两处动作统一变为“确认修改并返回探究问题”，并提供撤销。确认后 P02 按完整 P01 快照重建并标记需要再次确认。
7. IndexedDB 继续复用同一数据库和独立 P02 store；没有新依赖、状态库、表单库或路由库。
8. P02 确认后只显示成功反馈和 P03 尚未开放边界，不创建假入口。

## 3. 状态与边界覆盖

| 要求 | 实现 |
|---|---|
| 正常 | P01 同款双栏；类型四选一；重点二选一；按需修改中心问题；右侧即时摘要；确认 |
| 加载 | 已确认情境保持可读；建议区骨架，不出现重复表单 |
| 空/校验 | P01 未给初步方向时只追问一句；无意义、超长、个人信息、答案预设、超课时均有具体错误 |
| 系统失败 | 保留本机方案和教师编辑；补充建议失败不阻塞手工确认 |
| 不可用/无权限 | 统一安全结果，不回显课次、教材或问题 |
| 超时/离线 | 显示 30 秒语义或离线边界；本机预生成方案仍可编辑，不假装在线成功 |
| 成功 | `探究问题已确认`；P03 尚未开放，不伪造跳转 |
| 返回/恢复 | 桌面 rail、手机摘要和 P01 主动作可双向切换；查看不制造警告；实际修改才要求确认并重建 P02；可撤销修改 |
| 手机 | 390px/320px 单列；按钮至少 44px；无水平溢出 |
| 键盘/焦点 | 原生控件；错误自动展开编辑区并聚焦首错；2.4px 独立焦点环 |

前端步骤和不可用展示只改善体验，不构成安全授权。
