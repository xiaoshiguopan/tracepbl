# 学习卡：阶段 6.8 P06“设计活动”

> 日期：2026-09-02

## 本轮学到什么

1. 教师需要的是一份能直接审阅的课堂节奏，而不是另一张从零填写的教案表；先排出完整 45 分钟，再让其局部校准能显著减少操作。
2. “学生动作 → 使用史料 → 留下成果”比单独显示活动标题更能暴露空泛任务：中间的史料一旦拿掉，活动是否仍能完成会立刻可见。
3. 转换、分组和提交时间必须进入同一本时间账簿。把它们藏在任务文案中会制造看似合时、实际超时的课堂方案。
4. 匿名学情可以落实为“本活动最可能卡住的地方”和对应支架，不需要收集班级号、姓名或学生画像。

## 实现中暴露的问题

- 页面图中的活动像连续排演谱，但旧规格仍写“活动卡”。本轮同步页面规格、状态矩阵和组件职责，避免后续把旧名误当成必须实现的卡片墙。
- 状态导航在同一路由快速切换时会受懒加载影响；最终用独立新标签页确认 5 秒加载骨架，避免把路由级 fallback 错当成 P06 局部加载状态。
- 静态 HTML 会在数字和单位之间插入标签边界，最初页面结构测试用纯文本匹配产生假失败；改为验证实际结构，不改产品文案掩盖测试问题。

## 后续约束

- P07 仍按固定流程先讨论方案、生成页面图、用户确认后编码，并继续使用 P01 视觉母版。
- P07 必须直接承接本页的可观察成果，不能生成与活动脱节的通用量规。
- 当前合成活动和支架只验证交互；未来 AI 方案需要提示词约束、结构化输出和教师任务评测，不能用本 fixture 冒充模型能力。
