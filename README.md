# 零基础 Vibe Coding 全流程模板包

这是面向 Windows + Codex 的学习型项目模板。它不预设产品方向，也不预设技术栈。

## 唯一必读入口

先完整阅读 `VIBE-CODING-AI-GUIDE.md`。它既是给新手看的总手册，也是可直接交给 AI 执行的项目推进协议。

首次使用时，优先在 Codex 本地任务中发送 `00-START-HERE.md` 的启动对话，让 AI 自动创建目录、初始化 Git、复制模板并完成阶段 0 检查。只有 Codex 权限或界面确实无法代办时，用户才执行一个最小人工动作。不要先生成应用代码、安装框架或注册云服务。

## 不可绕过的规则

1. 先初始化 Git，再进行调研和立项。
2. 立项与优秀案例研究完成后，AI 用证据选择唯一技术栈；此前不得搭脚手架。
3. 规划、规范和架构规则先完成，经用户确认后才能设计。
4. 严格按“前端设计并确认 → 前端全部编码 → 数据库设计并确认 → 数据库全部编码 → 后端设计并确认 → 后端全部编码 → 集成和总审查”推进。
5. 每个子阶段结束，AI 先汇报；用户明确回复“批准归档”后，才可本地 Git 归档。
6. 推送、部署、生产迁移和其他外部动作另行授权。
7. 文档放 `docs/`，代码放技术决策确定的代码目录，二者不得混放。
8. 立项后生成 `PROJECT-HANDBOOK.md`；每次开工都必须阅读。
9. 项目完成和质量安全验收前只使用合成数据；真实数据单独审查、批准和导入，永不进入 Git。
10. 最终发布到 GitHub Public 仓库，并提供任何人可直接打开的公开体验 URL。
11. AI 能安全完成的本地机械操作全部由 AI 代办；不得把创建目录、复制模板、执行 Git 检查等步骤甩给零基础用户。

## 文件说明

- `VIBE-CODING-AI-GUIDE.md`：完整流程、门禁、模板、清单和启动提示词。
- `00-START-HERE.md`：第一次启动的最短操作说明。
- `AGENTS.md`：在项目专属规范尚未生成前约束 AI 的引导规则。
- `prompts/`：快捷提示词；以总手册为最高准则。
- `docs/`：可选的空白模板；实际目录以总手册和技术决策为准。
- `checklists/`：辅助核对，不代替阶段报告和用户批准。

模板中的 `[填写]` 必须替换为真实内容。未实际验证的项目必须标记“未验证”，不能勾选为完成。
